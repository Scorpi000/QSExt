# 技术选型

## 推荐技术栈

| 层 | 技术 | 理由 |
|---|------|------|
| **前端** | React + TypeScript | 生态成熟，组件库丰富，适合复杂交互 |
| **UI 组件** | Ant Design | 企业级组件库，表格/表单/图表支持完善 |
| **图表** | ECharts + Plotly | ECharts 做仪表盘，Plotly 做金融分析（与现有代码复用） |
| **DAG 可视化** | React Flow | 比 ipycytoscape 更强大，支持自定义节点/边 |
| **后端** | FastAPI | Python 原生，异步支持好，自动生成 OpenAPI 文档 |
| **状态管理** | Zustand (前端) + Redis (后端) | 前端轻量状态，后端缓存计算结果 |
| **数据库** | PostgreSQL (用户/权限) + 现有 Neo4j/ClickHouse | 用户管理用 PG，业务数据复用现有 |
| **部署** | Docker Compose | 小团队自部署，一键启动 |

## 备选方案对比

### Python 全栈（Streamlit/Dash/Gradio）

**优点**：
- 开发速度快，纯 Python 代码
- 与 QuantStudio 无缝集成

**缺点**：
- 复杂交互支持差（拖拽、多面板、右键菜单）
- 布局灵活性有限
- 状态管理能力弱

**结论**：适合快速原型，不适合全功能平台

### Jupyter 扩展（JupyterHub/JupyterLab）

**优点**：
- 与现有 Notebook 工作流集成
- 复用现有 ipywidgets 代码

**缺点**：
- widget 模型限制布局灵活性
- 现有 Notebook GUI 已遇布局瓶颈（Tab 嵌套、对话框堆叠）
- 多用户支持需要 JupyterHub 配置

**结论**：保留现有 Notebook GUI，Web 版独立开发

### 桌面 Electron 应用

**优点**：
- 跨平台桌面应用
- 可复用前端代码

**缺点**：
- 安装部署复杂
- 不适合团队协作
- 资源占用高

**结论**：不适合小团队场景

## 详细技术说明

### 前端技术栈

#### React + TypeScript

```typescript
// TypeScript 提供类型安全
interface Factor {
  qsid: string;
  name: string;
  description: string;
  factorType: 'atomic' | 'derivative';
}

// React 组件化开发
const FactorCard: React.FC<{ factor: Factor }> = ({ factor }) => {
  return (
    <Card title={factor.name}>
      <p>{factor.description}</p>
    </Card>
  );
};
```

#### Ant Design

企业级 UI 组件库，提供：
- Table：支持虚拟滚动、列排序、筛选
- Form：动态表单、表单验证
- Tree：树形选择器（因子浏览）
- Chart：基于 @ant-design/charts 的图表组件

#### React Flow

DAG 可视化库，支持：
- 自定义节点类型（因子、因子表、因子库）
- 节点拖拽和连线
- 缩放和平移
- 自动布局算法

#### ECharts + Plotly

- **ECharts**：仪表盘、统计图表，性能好
- **Plotly**：金融分析图表（K线、净值曲线），与现有 Python 代码复用

### 后端技术栈

#### FastAPI

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class FactorInfo(BaseModel):
    qsid: str
    name: str
    description: str

@app.get("/api/factors/{qsid}", response_model=FactorInfo)
async def get_factor(qsid: str):
    # 调用 QuantStudio API
    factor = qs_registry.get_factor_info(qsid)
    return FactorInfo(**factor)
```

优点：
- 自动生成 OpenAPI 文档（Swagger UI）
- 原生异步支持
- Pydantic 数据验证
- WebSocket 支持（任务进度推送）

#### Redis

用于：
- 缓存频繁查询的因子元数据
- 存储异步任务状态
- 会话管理（多用户）

### 数据库

| 数据库 | 用途 | 说明 |
|--------|------|------|
| PostgreSQL | 用户管理、权限、配置 | 新增，存储用户信息和系统配置 |
| Neo4j | 计算图元数据 | 复用现有 QSRegistry |
| ClickHouse | 因子数据存储 | 复用现有 FactorDB |
| Redis | 缓存、会话、任务队列 | 新增 |
