# 实时监控预警系统

## 一、概述

实时监控预警是策略失效分析体系的**日常运行层**。目标是在策略出现退化的最早阶段发出预警，避免等到大幅回撤才被动应对。

**核心设计原则**：
- L1 指标必须计算简单、数据可得、时效性高
- 预警必须区分噪声波动和真实退化（统计显著性检验）
- 多指标联合预警比单一指标更可靠

## 二、Z-score 信号健康度评级

### 2.1 核心方法

**来源**：Signal Decay Monitor 框架

持续比较近期胜率/收益与历史基线，通过 Z 检验判断退化是否统计显著。

```
Z = (近期均值 - 历史均值) / (历史标准差 / √n)

若 Z < -1.96（95% 置信），信号已统计显著退化
```

### 2.2 四级健康度评级

| 状态 | Z-Score 范围 | 置信度 | 行动 |
|------|-------------|--------|------|
| 🟢 **健康** | > -0.5 | — | 正常交易，维持现有参数 |
| 🟡 **减弱** | -0.5 ~ -1.5 | ~70% | 收紧止损，密切关注后续变化 |
| 🟠 **退化** | -1.5 ~ -2.5 | ~95% | 显著降低仓位或暂停加仓 |
| 🔴 **死亡** | < -2.5 | ~99% | 立即停止该信号交易，启动策略审查 |

### 2.3 置信带可视化

```
绘制近期表现的时间序列 + 历史基线均值 ± 1σ / 2σ 置信带
- 超出 1σ 带 = 黄色预警
- 超出 2σ 带 = 红色预警
```

## 三、日常监控仪表盘

### 3.1 每日监控指标

| 指标 | 计算频率 | 为何重要 | 预警规则 |
|------|---------|---------|---------|
| **信号 Rank IC** | 每日 | 预测能力的直接度量 | 滚动 60 日均值 < 0.02 |
| **信号换手率** | 每日 | 无需未来数据，实时可测 | > 15%/天 = 危险 |
| **超额收益 Z-score** | 每日 | 策略表现是否偏离常态 | < -1.5 |
| **最大回撤** | 每日 | 当前回撤 vs 历史最大回撤 | 达到历史最大回撤的 80% |

### 3.2 每周监控指标

| 指标 | 计算频率 | 预警规则 |
|------|---------|---------|
| **ICIR** | 每周（滚动 12 周） | < 0.5 预警 |
| **因子暴露漂移** | 每周 | 任一风格暴露偏离历史均值 > 1σ |
| **行业集中度 HHI** | 每周 | 超过滚动 1 年均值 + 2σ |
| **Brinson 选股效应** | 每周 | 连续 4 周为负 |
| **信号自相关** | 每周 | 1阶自相关 < 0.6 且下降趋势 |

### 3.3 每月监控指标

| 指标 | 预警规则 |
|------|---------|
| **IC 衰减曲线** | 曲线整体下移或形状改变 |
| **Barra 风格收益贡献** | 残差 Alpha 持续为负 |
| **信号半衰期重估** | 半衰期缩短 > 30% |
| **因子拥挤度综合评分** | > 0.7（高拥挤） |
| **市场状态条件表现** | 任一状态下连续 3 个月超额为负 |

## 四、多指标联合预警

### 4.1 预警矩阵

| 情景 | IC 下降 | 换手率上升 | 拥挤度上升 | 因子暴露漂移 | 含义 | 响应级别 |
|------|--------|-----------|-----------|------------|------|---------|
| A | ✅ | ❌ | ❌ | ❌ | 纯信号退化 | 🟡 关注 |
| B | ✅ | ✅ | ❌ | ❌ | 信号不稳定 | 🟠 降仓 |
| C | ✅ | ✅ | ✅ | ❌ | 信号失效 + 拥挤 | 🔴 清仓 |
| D | ❌ | ❌ | ❌ | ✅ | 风格切换 | 🟡 关注 |
| E | ❌ | ❌ | ✅ | ✅ | 拥挤 + 风格漂移 | 🟠 降仓 |
| F | ✅ | ✅ | ✅ | ✅ | **全面退化** | 🔴 策略暂停 |

### 4.2 预警规则引擎

```python
def evaluate_warning_rules(metrics):
    """多指标联合预警评估"""
    
    score = 0
    reasons = []
    
    # 信号退化（权重最高）
    if metrics['rolling_ic_60d'] < 0.02:
        score += 3
        reasons.append(('信号', 'IC 连续 3 个月低于 0.02'))
    
    # 换手率异常
    if metrics['daily_churn'] > 0.15:
        score += 2
        reasons.append(('换手率', f"日换手率 {metrics['daily_churn']:.1%} > 15%"))
    
    # 拥挤度上升
    if metrics['crowding_score'] > 0.7:
        score += 2
        reasons.append(('拥挤度', f"拥挤度评分 {metrics['crowding_score']:.2f}"))
    
    # 超额收益 Z-score
    if metrics['excess_return_z'] < -1.5:
        score += 1
        reasons.append(('超额收益', f"Z-score {metrics['excess_return_z']:.2f}"))
    
    # 因子暴露漂移
    if metrics['max_exposure_drift'] > 1.0:
        score += 1
        reasons.append(('暴露漂移', f"最大暴露漂移 {metrics['max_exposure_drift']:.2f}σ"))
    
    # 评级
    if score >= 6:
        level, action = '🔴 严重', '暂停策略，启动全面审查'
    elif score >= 4:
        level, action = '🟠 警告', '降低仓位至 50%，加强监控频率'
    elif score >= 2:
        level, action = '🟡 关注', '维持仓位，加密监控至每日'
    else:
        level, action = '🟢 正常', '维持正常交易'
    
    return WarningReport(score=score, level=level, action=action, reasons=reasons)
```

## 五、自动告警机制

### 5.1 告警渠道

| 级别 | 渠道 | 频率 |
|------|------|------|
| 🟡 关注 | QSWeb 仪表盘标记 | 每日 |
| 🟠 警告 | 企业微信/钉钉通知 | 实时 |
| 🔴 严重 | 邮件 + 即时消息 + 电话 | 实时 |

### 5.2 告警冷却

- 同一预警类型在 N 天内不重复发送
- 预警升级时立即发送，不受冷却限制
- 预警解除时发送恢复通知

## 六、策略健康度趋势报告

### 6.1 报告结构

```
策略健康度月报
├── 综合评分（0-100）
├── 分项得分
│   ├── 信号质量：ICIR / 半衰期 / 换手率
│   ├── 收益归因：Brinson 选股效应 / 残差 Alpha
│   ├── 适应性：最差状态表现 / MRP
│   ├── 拥挤度：综合拥挤评分
│   └── 风险：因子暴露漂移 / 行业集中度
├── 变化趋势（vs 上月 / vs 去年同期）
├── 预警一览
└── 建议行动
```

### 6.2 趋势可视化

- 各指标的时间序列图（带预警阈值线）
- 蜘蛛图：当前 vs 历史平均
- 热力图：各市场状态下的绩效变化
- 健康度仪表盘：综合评分的历史趋势

### 7.3 与现有模块的关系

监控报告节点会调用其他分析模块的工具类获取指标：
- `SignalQualityDiagnostics` → IC / 换手率 / 半衰期
- `PerformanceAttribution` → Brinson 选股效应 / 残差 Alpha
- `FactorCrowdingAnalysis` → 拥挤度评分
- `StrategyRegimeAnalyzer` → MRP

这种编排通过 BTNode 的 deps 机制或在 `backward_compute` 中直接实例化工具类来实现。
