# 策略失效分析体系 —— 整体架构设计

## 一、目标与定位

给定一个投资策略（选股策略或 ETF 轮动策略为起点），本分析体系的目标是回答三个核心问题：

1. **策略有没有失效？**（快速诊断，L1 层）
2. **失效的原因是什么？**（归因拆解，L2 层）
3. **应该往哪个方向优化？**（根因定位与建议，L3 层）

## 二、六维度分析框架

```
策略失效分析体系
├── 信号质量诊断    ← 第一入口：信号预测能力是否衰减？
├── 收益归因分析    ← 收益来源拆解：Alpha 还是 Beta？
├── 市场状态适应性  ← 什么市场环境下策略失效？
├── 因子拥挤度分析  ← 策略是否因拥挤而失效？
├── 回撤归因分析    ← 最大亏损由什么驱动？
└── 实时监控预警    ← 如何第一时间发现策略退化？
```

## 三、三层深度设计

| 层级 | 定位 | 时效性 | 典型场景 |
|------|------|--------|---------|
| **L1 快速诊断** | 日常监控，秒~分钟级 | 每日/盘中 | 策略表现异常时首先查看 |
| **L2 归因拆解** | 定向排查，分钟级 | 每周/每月 | L1 报警后深入定位问题 |
| **L3 深度分析** | 根因定位，可离线 | 季度/按需 | 策略迭代前全面审查 |

## 四、各层包含的分析模块

### L1 快速诊断

| 模块 | 说明 | 时效 |
|------|------|------|
| 信号 IC 滚动监控 | 滚动 Rank IC + ICIR，最核心的领先指标 | 每日 |
| 信号换手率异常检测 | 日频换手率监控，无需未来数据 | 每日 |
| 收益 Z-score 偏离预警 | 近期超额 vs 历史分布的 Z 检验 | 每日 |
| 因子暴露漂移 | 风格因子暴露 vs 历史均值 | 每周 |

### L2 归因拆解

| 模块 | 说明 |
|------|------|
| Brinson 收益归因 | 配置效应 vs 选股效应 |
| Barra 风格因子归因 | 市场/行业/风格/残差 四级分解 |
| 市场状态适应性分析 | 各市场状态下的策略表现 |
| 回撤期归因矩阵 | 多维度分解回撤来源 |

### L3 深度分析

| 模块 | 说明 |
|------|------|
| 信号半衰期估计 | Rank Autocorrelation 方法 |
| 信号分布漂移检测 | KS 检验 + 自相关 + Wasserstein 距离 |
| 因子拥挤度测量 | 多指标综合评分 |
| HMM 状态识别 | 无监督市场状态划分 |
| 压力测试 | 历史极端情景回放 + 参数敏感性 |
| 失效传导分析 | 因子失效 → 信号失效 → 收益回撤的传导链 |

## 五、数据依赖关系

```
输入数据
├── 策略持仓数据（必需）
├── 基准持仓数据（归因必需）
├── 因子值数据（信号诊断必需）
├── 行业分类数据（Brinson 归因必需）
├── 风格因子数据（Barra 归因必需）
│   └── Size / Value / Momentum / Volatility / Quality / Growth 等
├── 行情数据（收益计算必需）
└── 市场状态数据
    └── 波动率 / 均线 / 行业收益离散度 等
```

## 六、QuantStudio 框架集成

### 6.1 整体设计原则

所有分析模块统一基于 QuantStudio 的 `BTNode`（回测计算节点）体系实现，而非独立的纯 Python 类。

**核心理由**：
- **计算图复用**：BTNode 接入 QuantStudio 的 DAG 计算引擎，自动管理数据依赖、时点对齐、并行执行
- **Factor 体系**：输入输出均为 Factor 对象，与因子算子（FactorOperator）、因子表（FactorTable）无缝对接
- **报告聚合**：所有 BTNode 的输出可通过 `BTReport` 聚合为统一 HTML 报告
- **缓存与持久化**：通过 `FactorCache` 机制避免重复计算

### 6.2 统一模式

```
┌─────────────────────────────────────────────────────────────┐
│  分析模块（BTNode 子类）                                      │
│                                                              │
│  __init__(deps=[Factor, ...])                                │
│  ├── deps[0]: 策略净值 / 账户 Factor                          │
│  ├── deps[1]: 基准净值 Factor（可选）                         │
│  ├── deps[2]: 标签 / 信号 Factor（按需）                     │
│  └── ...                                                     │
│                                                              │
│  backward_compute(bwd_data_list) → dict                      │
│  ├── 从 bwd_data_list 提取各 dep 的 DataFrame 结果           │
│  ├── 调用已有的独立分析工具（如 StrategyRegimeAnalyzer）       │
│  └── 返回 Output dict: {指标名: DataFrame, ...}              │
│                                                              │
│  genReport(output) → HTML                                    │
│  └── 参数设置 + 格式化表格 + matplotlib 图表（base64 内嵌）   │
└─────────────────────────────────────────────────────────────┘
```

### 6.3 模块 → BTNode 映射

| 分析模块 | BTNode 类名 | deps | 说明 |
|---------|-------------|------|------|
| 信号质量诊断 | `SignalQualityReport` | `SignalFactor` × N, `ReturnFactor` | IC 分析、漂移检测等 |
| 收益归因分析 | `AttributionReport` | `PortfolioNV`, `BenchmarkNV`, `IndustryFactor` | Brinson + Barra 归因 |
| 市场状态适应性 | `RegimePerformanceReport` | `StrategyNV`, `RegimeLabel` | 状态表现 + 热力图 + MRP ✅ 已实现 |
| 因子拥挤度分析 | `CrowdingReport` | `FactorValue` × N, `HoldingsFactor`, `MarketDataFactor` | 多指标拥挤度评分 |
| 回撤归因分析 | `DrawdownReport` | `PortfolioNV`, `HoldingsFactor`, `BenchmarkNV` | 回撤识别 + 多维归因 |
| 实时监控预警 | `MonitoringReport` | `StrategyNV`, `SignalFactor` × N | Z-score 评级 + 联合预警 |

### 6.4 独立工具层

分析逻辑保留在独立的工具类中（如 `StrategyRegimeAnalyzer`、`DrawdownAttribution`），BTNode 的 `backward_compute` 中实例化并调用它们。这样：
- 工具类可独立使用（脚本、Jupyter）
- BTNode 提供框架集成（计算图、报告聚合）

### 6.5 报告聚合示例

```python
from QuantStudio.BackTest.BackTestModel import BTReport

# 创建各维度分析节点
regime_report = RegimePerformanceReport(nv=NV, regime_label=label, args={"GenReport": True})
crowding_report = CrowdingReport(factor_value=F1, ...)
drawdown_report = DrawdownReport(portfolio_nv=NV, ...)

# 聚合为统一报告
full_report = BTReport(bt_node_list=[regime_report, crowding_report, drawdown_report])

# 执行
Rslt = ExecEngine.run([full_report], context, ...)
print(Rslt[0]["Report"])  # 包含所有模块的 HTML 报告
```

## 七、与现有 QSExt 基础设施的集成点

| 现有组件 | 集成方式 |
|---------|---------|
| `FactorDB` 因子库 | 读取因子值数据，计算 IC/ICIR |
| `StrategyDef` 策略定义 | 获取策略元信息和依赖因子 |
| `QSRegistry` 图数据库 | 查询策略依赖链、因子关系 |
| `BackTest` 回测引擎 | `BTNode` 子类接入 DAG 计算图，自动管理依赖和时点 |
| `FactorOperator` 算子 | 市场状态划分等信号变换通过算子链实现 |
| `BTReport` 报告聚合 | 各分析模块的 Output dict 聚合为统一 HTML 报告 |
| `QSWeb` 前端 | 展示监控仪表盘和分析报告 |

## 八、实施优先级

### 第一期：核心诊断（快速见效）

1. IC 滚动监控（Rank IC + ICIR + IC 衰减曲线）
2. Brinson 收益归因（配置 vs 选股）
3. 市场状态划分（简单阈值法）+ 状态条件表现
4. 基础监控面板（QSWeb 集成）

### 第二期：深度归因

5. Barra 风格因子暴露归因（复现 CNE6 主要因子）
6. 回撤归因矩阵（多维度分解）
7. 信号半衰期估计（Rank Autocorrelation）
8. 信号分布漂移检测（KS 检验 + 自相关）

### 第三期：高级功能

9. 因子拥挤度测量（多指标综合评分）
10. HMM 状态识别（无监督市场状态发现）
11. 压力测试框架（历史极端情景 + 参数敏感性）
12. 自动化预警（邮件/企业微信告警）
