# 工作台组件与服务目录

QSExt Graph 提供与 Web 框架无关的组件列表加载、元信息提取和构图协议。QSWeb 的页面与部署说明见同级仓库 `QSWeb/docs/13-统一计算图工作台.md`。

## 组件列表

调用 `QSExt.Graph.api.load_component_directory(path)`，递归导入目录下的 Python 模块，按相对路径排序。仅注册各模块 `COMPONENTS` 列表中的内容，`CATEGORY` 为可选默认分类。普通导入和辅助模型不会被扫描为组件；文件名不限于 definition.py，不声明列表的文件可作为辅助模块。不调用 register 函数，也不使用 __all__ 作为公开范围。

```python
"""服务中开放的组件。"""
from QuantStudio.Factor.FactorOperator import RollingMean
from QSExt.Graph.api import Component

CATEGORY = "因子加工"

COMPONENTS = [
    RollingMean,
    Component(RollingMean, id="research.mean", title="滚动均值"),
]
```

上例展示直接公开类和覆盖元信息两种写法，实际使用通常保留其中一种。直接列出的类必须是 Node 或 FactorOperator 的具体子类。算子自动提取 __QS_ArgClass__、__QS_InputClass__，节点自动提取 __QS_ArgClass__、__QS_DepClass__，不调用构造器获取元信息。必须通过其他位置参数构造的算子应改用带 builder 的组合声明。

Component(target, id=None, title=None, category=None, version=1) 可覆盖普通类的目录属性；组合组件声明 args_model、input_model、output_type 和 builder，target 留空。版本默认为 1，标题默认取类名或构图函数名，说明取文档字符串。分类依次取组件覆盖、文件 CATEGORY、类别默认值。

库内类的自动标识为原始模块名加类名；服务内类使用 components.<相对模块路径>.<类名>。不包含绝对路径或源码摘要；移动文件会改变默认标识，需要固定标识时显式提供 id。组合组件未填写 id 时根据 builder 生成。

## 目录与脚本路径

组件库直接按 components 的实际目录展示，没有固定板块或目录名称映射，也不会将自定义目录归入“其他”。目录可任意命名和嵌套；根目录脚本直接位于树的顶层。加载器将列出 COMPONENTS 的脚本的完整相对路径保存到 source_path，不再提供 section 字段。

例如 research/time/rolling.py 中导入并列出的库算子，source_path 仍为 research/time/rolling.py，不会变成库内的 FactorOperator.py。source_category 单独记录该脚本的 CATEGORY，不受单个 Component.category 覆盖。QSWeb 按“实际目录 → 子目录 → 脚本类别 → 组件”呈现目录树；脚本节点优先显示 CATEGORY，未声明时显示去掉 .py 后缀的文件名。未公开组件的辅助模块及不含组件的目录不显示。同名类别按真实脚本路径区分，原始路径可通过悬停查看和搜索。图中实例的动态描述保留同样的 source_path/source_category。

registry.locations 记录每个已注册 ID/版本的相对声明路径；它与 registry.sources 的文件摘要分离，不写入图文档或计算节点。目录调整不会改变显式组件 ID。

目录展示名来自对应目录 __init__.py 的 CATEGORY；文件缺失或未声明 CATEGORY 时使用目录名。__init__.py 不必声明 COMPONENTS，每层类别独立，不继承父目录或脚本类别。registry.directory_categories 保存“相对目录路径 → 类别”的映射；每个 DefinitionDescriptor.directory_categories 只返回所属目录及祖先目录的类别。CATEGORY 使用非空字符串校验，目录类别支持搜索，同名类别按真实路径区分。components 根目录本身不作为树节点展示。

```python
# components/research/__init__.py
CATEGORY = "研究组件"
```

## 组合组件

```python
COMPONENTS = [
    Component(
        id="research.ic", title="IC 分析",
        args_model=WindowArgs, input_model=PriceInputs,
        output_type=IC, builder=build_ic,
    ),
]
```

模型和 build_ic 由服务定义文件提供。builder 签名为 builder(block, args, inputs)，args 是完成参数校验后的值及默认值，inputs 为已解析的上游对象或资源描述。返回值必须符合 output_type。加载器先登记所有出口类型，再生成描述，使报告输入能检查具体分析结果，不依赖文件顺序。组件作者无需调用 registry 或手动创建 TypeDescriptor。

APPLICATION_COMPONENTS 为应用已有算子和节点模板的通用列表，SOURCE_COMPONENT 为延迟资源来源声明，可显式展开或加入服务的 COMPONENTS。二者不会由加载器隐式注册。服务级回测、策略和报告见 QSWeb/examples/service/components；QSExt Graph 的 Workbench 模块仅保留通用运行工具，不再维护业务组件注册表。

## 加载约定

支持带或不带 __init__.py 的目录及包内相对导入，每个模块在同一加载批次只执行一次。直接读取当前源码，不依赖 pyc 时间戳缓存。目录不存在、没有非空组件列表、列表类型错误、无效项、重复 ID/版本或模型错误均阻止启动，错误包含文件及 COMPONENTS 下标。失败时清理本次新导入的服务模块，不发布部分目录；成功后冻结 DefinitionRegistry。

registry.sources 保存组件目录内 Python 源文件摘要。修改定义后重启服务，加载器不调用旧的 register(registry) 入口。模块顶层只声明组件，不连接数据库、不创建业务对象、不执行计算；这属于组件作者必须遵循的契约。

## 回测与策略运行

分析组件在 construction_scope(dates, section_ids, module_directory=None) 内构图，通过 get_construction_context() 读取本次运行快照。显式分析截面优先于运行默认截面；calculation_dates 从实际时点选取周期末时点。module_directory 为运行期脚本目录，调用方负责执行完成后的清理。

Python 策略入口为 build_strategy(args, factors, price)，返回账户 Factor。代码、别名和参数属于图文档，脚本输入按集合顺序与别名配对。静态校验仅检查参数声明和 Python AST，不执行脚本；build_script 只在显式任务的构图阶段调用。

## 执行资源与验证

ResourceFactor 在 init 阶段汇集时点与截面，prepare 阶段通过 ResourceResolver 读取并冻结 DataFrame，compute 阶段只进行索引。静态校验与 compile_graph 不解析活动连接。

因子库和 Factor 的 readData 使用独立 FactorContext 与顺序引擎，避免嵌套运行清空外层图的 NodeState/PrepareNodeDict 或改变外层事件归属。嵌套上下文继承日期标尺、资源及数据版本，不继承外层缓存和事件回调。tests/test_Graph_Sources.py 使用真实临时 HDF5 因子表验证双来源与派生因子读取。

运行时使用 GraphContext；并行切分保留准备后的数据，移除主进程资源解析器和应用回调。QuantStudio ParallelEngine 通过消息队列传递节点事件。运行资源的连接与关闭由调用方管理。

回归测试：QSExt/tests/test_Graph_Components.py 验证显式列表、相对导入、稳定标识、组合构图与错误定位；其他 test_Graph*.py 验证协议和编译。QSWeb/tests/test_graph_workbench.py 验证六类分析与报告、IC 数值、策略及双进程来源执行；服务初始化测试验证组件模板可在新目录直接加载。
