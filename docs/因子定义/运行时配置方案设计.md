# FactorDef 运行时配置方案设计

## 1. 背景与问题

早期 `scripts/` 下的执行脚本在构造 `FactorDefInput` 时，各类参数全部硬编码在脚本中：

| 硬编码项 | 问题 |
|---|---|
| JYDB 连接参数 | 切换环境需改代码 |
| HDF5 数据目录 | 路径与机器绑定 |
| 缓存目录 | 同上 |
| 模块列表 | 新增因子模块需改脚本 |
| 时间范围计算逻辑 | 多个脚本中重复 |
| ID 选取逻辑 | debug/prod 切换靠三元表达式 |
| 并发数 | 硬编码默认值 |
| Neo4j 配置 | 路径硬编码 |
| 嵌入模型参数 | 硬编码 |

除此之外，还有一个**架构层面的局限**：

> 早期脚本假定数据源**只有 JYDB**，输出目标**只有 HDF5DB**。但实际上 QuantStudio 提供了多种 `FactorDB` 实现（BaoStockDB、SQLDB 等），未来还可能接入更多数据源。配置文件需要统一描述**任意类型、任意数量的因子库**。

这导致：
- **切换环境**需要改代码或复制脚本
- **新增因子模块**需要修改脚本中的 `ModuleList`
- **接入新数据源**需要改写 DB 连接逻辑
- **CI/CD 集成**困难，参数无法从外部注入

## 2. 设计目标

1. **配置与逻辑分离**：运行参数通过配置文件注入，脚本只保留执行逻辑
2. **最大灵活性**：配置文件是 `.py` 文件，支持任意 Python 表达式、条件判断、环境变量读取
3. **多数据源支持**：可以配置任意类型、任意数量的因子库，统一管理连接生命周期
4. **多环境支持**：通过不同的 settings 文件切换环境，无需改代码
5. **渐进式采用**：现有脚本可以逐步迁移
6. **自文档化**：配置文件中的每个字段都有注释说明

## 3. 配置文件设计

### 3.1 文件位置与命名约定

```
your_project/factor_defs/conf/
├── settings.py              # 默认配置
├── settings_dev.py          # 开发环境覆盖
├── settings_prod.py         # 生产环境覆盖
└── settings_local.py        # 本地覆盖，不入库（.gitignore）
```

框架在 `QSExt/FactorDef/conf/` 提供 `settings.example.py` 作为模板。

加载优先级（后者覆盖前者）：
```
settings.py  →  settings_{env}.py  →  settings_local.py  →  环境变量
```

### 3.1.1 变量命名与加载规则

`FactorDefSettings.from_module()` 按以下规则从 settings 模块提取配置变量：

**1. 大写变量提取**

settings 模块中所有 **全大写且不以 `_` 开头** 的变量会被自动提取：

```python
# settings.py 中                    # FactorDefSettings 字段名
FACTOR_DATABASES = [...]       →    factor_databases
PROXY_TABLE_MAPPING = {}       →    proxy_table_mapping
DEBUG = False                  →    debug
END_DT = "last_friday"         →    end_dt
WORKERS = 8                    →    workers
```

**2. 钩子函数**

小写函数名作为钩子单独提取：

| 钩子名 | 调用时机 | 用途 |
|---|---|---|
| `init_db(pool)` | 所有 DB 连接后 | 执行自定义初始化逻辑 |

**3. 环境变量覆盖**

以 `FACTORDEF_` 为前缀的环境变量会覆盖配置项：

```bash
export FACTORDEF_DEBUG=true
export FACTORDEF_WORKERS=4
export FACTORDEF_FACTOR_STORER_CONFIG='{"IfExists":"replace"}'
```

**4. 完整覆盖链**

```
settings.py  →  settings_{env}.py  →  settings_local.py  →  环境变量  →  命令行参数
```

### 3.2 配置项清单

```python
# ============================================================
# FactorDef 运行时配置
# ============================================================
# 环境切换方式：
#   python run_factor_def.py --settings settings_prod
# 或者通过环境变量：
#   FACTORDEF_SETTINGS_MODULE=settings_prod python run_factor_def.py

# ============================================================
# 1. 运行模式
# ============================================================

DEBUG = False                # True 时使用少量股票 ID
UPDATE_DATA = True           # 是否更新因子数据到目标库
REGISTER_GRAPH = False       # 是否注册因子到图数据库
DRY_RUN = False              # 仅分析不执行

# ============================================================
# 2. 因子数据库定义 (FACTOR_DATABASES)
# ============================================================
# 每个库的配置结构：
# {
#     "name": str,              # 逻辑名称（如 "JYDB"、"TDB"）
#     "class": str,             # 类名或完整路径
#     "role": str,              # "source" | "target" | "proxy"
#     "args": dict,             # 传给 FactorDB(args=...) 的参数
#     "config_file": str|None,  # 可选 JSON 配置路径
# }
#
# class 支持两种写法：
#   1. 短名: "JYDB", "HDF5DB", "SQLDB", "BaoStockDB"
#   2. 完整路径: "QuantStudio.Factor.JYDB.JYDB"

FACTOR_DATABASES = [

    # 数据源：聚源数据库 (只读)
    {
        "name": "JYDB",
        "class": "JYDB",
        "role": "source",
        "args": {"FTArgs": {"PreFilterID": False}},
    },

    # 输出目标：本地 HDF5 文件 (可写)
    {
        "name": "TDB",
        "class": "HDF5DB",
        "role": "target",
        "args": {"MainDir": r"D:\Data\HDF5DB_Test"},
    },

    # 代理缓存（可选）
    # {
    #     "name": "ProxyDB",
    #     "class": "HDF5DB",
    #     "role": "proxy",
    #     "args": {"MainDir": r"D:\Data\HDF5DB_Proxy"},
    # },
]

PROXY_TABLE_MAPPING = {}

# ============================================================
# 3. 时间范围
# ============================================================

END_DT = "last_friday"       # 支持: "today", "yesterday", "last_friday", "2026-04-05"
START_DT = None              # None 表示由 LOOKBACK 自动推算
LOOKBACK = 15
MAX_LOOKBACK = 365 * 10

# ============================================================
# 4. 交易日期与 ID 的数据源
# ============================================================

DT_SOURCE = "JYDB"
ID_SOURCE = "JYDB"

# ============================================================
# 5. ID 类型与因子模块 (ID_PROFILES)
# ============================================================
# 每个 profile 指定一个 IDType 维度的因子模块分组。
#
# factor_modules 支持两种格式：
#   字符串 — 模块路径，支持 glob:
#     "your_project.factor_defs.stock_cn_status"
#     "your_project.factor_defs.stock_cn_*"
#
#   字典 — 带 model_args 和 factor_meta 覆盖:
#     {
#         "module": "your_project.factor_defs.industry_cn_factor_from_stock",
#         "model_args": {"industry_factor": "sw2021_code_level1"},
#         "factor_meta": {"TargetTable": "custom_table_name"},
#     }
#
# id_selection 支持三种类型:
#   {"type": "all"}              — 全部 ID
#   {"type": "current"}          — 当前存续 ID
#   {"type": "list", "ids": [...]} — 指定 ID 列表
#
# proxy_tables 代理表控制（需配合 --use-proxy）:
#   None / "*" / ["table1", "table2"]

ID_PROFILES = [
    {
        "id_type": "A股",
        "id_selection": {"type": "all"},
        "factor_modules": [
            "your_project.factor_defs.stock_cn_status",
            "your_project.factor_defs.stock_cn_factor_*",
        ],
    },
]

# ============================================================
# 6. 输出配置
# ============================================================

TARGET_DB = "TDB"
FACTOR_STORER_CONFIG = {
    "IfExists": "update",
    "UpdateMeta": True,
}

# ============================================================
# 7. 缓存
# ============================================================

CACHE_DIR = r"D:\Data\Cache\FactorTaskCache"
CACHE_START_MODE = "new"
CACHE_SUFFIX = ".pkl"

# ============================================================
# 8. 执行引擎
# ============================================================

WORKERS = 8
PID_FORMAT = "0-{i}"

# ============================================================
# 9. 图数据库
# ============================================================

NEO4J_CONFIG_PATH = "~/QuantStudioConfig/Neo4jDBConfig.json"
EMBEDDING_MODEL = "bge-m3"
EMBEDDING_DIM = 1024
SKIP_EMBEDDING = False

# ============================================================
# 10. 日志
# ============================================================

LOG_LEVEL = "DEBUG"

# ============================================================
# 11. 钩子函数（可选）
# ============================================================
#
# def init_db(pool):
#     """在所有 DB 连接后调用"""
#     pool["JYDB"].setOutputMode("pandas")
```

### 3.3 配置项与 FactorDefInput 字段的映射关系

```
settings.py                              →  目标对象
────────────────────────────────────────────────────────────────────
FACTOR_DATABASES[role="source"]          →  FactorDefInput.FDB
FACTOR_DATABASES[role="proxy"]           →  build_dep_fd(proxy_db=...)
PROXY_TABLE_MAPPING                      →  build_dep_fd(proxy_table_mapping=...)
DT_SOURCE.getTradeDay(...)               →  FactorDefInput.DTs / DTRuler
ID_SOURCE.getStockID(...)                →  FactorDefInput.IDs
DEBUG                                    →  FactorDefInput.Debug
```

关键设计原则：

1. **配置不存查询结果，存查询策略** — `DTs`、`IDs` 等运行时获取
2. **因子库与用途解耦** — 库定义和用途指定分离
3. **同类型库可并存多个** — 通过 `name` 区分

### 3.4 多数据源场景示例

```python

    {"name": "HDF5Out", "class": "HDF5DB", "role": "target",
```

## 4. 核心类设计

### 4.1 架构概览

```
  settings.py (配置模块)
       │
       ▼
  FactorDefSettings    —— 从模块加载、合并、验证所有配置项
       │
       ├──→ FactorDBPool       —— 根据 FACTOR_DATABASES 创建、连接、管理所有因子库
       │
       └──→ FactorDefInputBuilder  —— 组合 Settings + DBPool，构造 FactorDefInput
                │
                ├── resolve_dts()      → DTs, DTRuler
                ├── resolve_ids()      → IDs, SectionIDs
                ├── resolve_fdb()      → FDB 字典
                └── build()            → FactorDefInput
```

所有核心类均位于 `QSExt.FactorDef.FactorDefContent`。

### 4.2 FactorDBPool — 因子库连接池

统一管理所有 `FactorDB` 实例的完整生命周期：

```python
from QSExt.FactorDef.FactorDefContent import FactorDBPool

pool = FactorDBPool(settings.factor_databases)
pool.create_all()        # 实例化
pool.connect_all()       # 连接
jydb = pool["JYDB"]      # 按名称访问
pool.disconnect_all()    # 断开
```

**关于"创建"**：

`create_all()` 处理 Python 对象的实例化，物理创建（建目录、建表）分情况：

| 场景 | 处理方式 |
|---|---|
| HDF5DB 目录创建 | `create_all()` 调用 `os.makedirs(MainDir, exist_ok=True)` |
| SQLDB 表/Schema 初始化 | `FactorStorer` 首次写入时自动完成 |
| 自定义初始化逻辑 | 在 settings 钩子中处理 |

### 4.3 FactorDefSettings — 配置对象

```python
from QSExt.FactorDef.FactorDefContent import FactorDefSettings

settings = FactorDefSettings.from_module("path.to.settings", debug=True)
```

### 4.4 FactorDefInputBuilder — FDI 构造器

```python
from QSExt.FactorDef.FactorDefContent import FactorDefInputBuilder

with FactorDefInputBuilder(settings) as builder:
    fdi = builder.build()               # FactorDefInput 已就绪
    modules = builder.resolve_modules() # 模块列表（含 glob 展开）
    # ... 运行因子定义 ...
# 退出 with 时自动断开所有因子库
```

## 5. 脚本改造示例

### 5.1 改造前

```python
def main(end_dt="last_friday", workers=8, debug=False):
    DataDir = r"D:\Data\HDF5DB_Test"
    SDB = JYDB(args={"FTArgs": {"PreFilterID": debug}}).connect()
    TDB = HDF5DB(args={"MainDir": DataDir}).connect()
    # 时间范围处理（~15 行）...
    FDI = FactorDefInput(FDB={"JYDB": SDB}, DTs=DTs, IDs=IDs, ...)
    ModuleList = [
        (stock_cn_status, {}, None),
        (stock_cn_industry, {}, None),
        # ... 硬编码模块列表
    ]
    for iModule, iModelArgs, iTargetTable in ModuleList:
        FDI.ModelArgs = iModelArgs
        iFactorDef = iModule.defFactor(fdi=FDI)
```

### 5.2 改造后

```python
from QSExt.FactorDef.FactorDefContent import FactorDefSettings, FactorDefInputBuilder

def main(settings_path: str = "settings", **cmd_overrides):
    settings = FactorDefSettings.from_module(settings_path, cmd_overrides=cmd_overrides)

    with FactorDefInputBuilder(settings) as builder:
        fdi = builder.build()
        modules = builder.resolve_modules()

        for module, model_args, _ in modules:
            fdi.ModelArgs = model_args
            factor_def = module.defFactor(fdi=fdi)
            # ... FactorStorer, QSGraphDB 等
```

### 5.3 CLI 使用

## 6. 模块发现机制

模块通过**完整 Python 导入路径**指定，支持 glob 模式。`FactorDefInputBuilder.resolve_modules_for()` 内部使用 `expand_glob()` 展开通配符（基于 `pkgutil.iter_modules`，不扫文件系统）。

```python
# glob 展开
from QSExt.FactorDef.utils import expand_glob
expand_glob("your_project.factor_defs.stock_cn_*")
# → ['your_project.factor_defs.stock_cn_status', ...]
```

## 7. 多品类 / 多数据源扩展

同一套 settings 机制支持不同品类和数据源组合：

```bash
# A股因子
python run_factor_def.py --settings settings_stock_cn

# 指数因子
python run_factor_def.py --settings settings_index_cn

# ETF因子
python run_factor_def.py --settings settings_mf_etf_cn
```
