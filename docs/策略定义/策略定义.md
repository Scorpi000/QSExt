# StrategyDef —— 策略定义框架

StrategyDef 提供策略定义的完整框架，与 FactorDef 架构对齐。核心职责：**策略元信息声明 → 依赖自动解析 → 运行时配置管理 → 执行调度**。

## 快速开始

### 1. 编写策略定义模块

```python
# my_strategies/ma_cross.py
import pandas as pd
from QuantStudio.BackTest.Strategy.Strategy import MakeStrategy
from QSExt.StrategyDef.StrategyDefContent import StrategyDefInput

# ---- 元信息 ----
__STRATEGY_META__ = {
    "TargetTable": "strategy_signals",     # 必填：信号输出的因子表名
    "IDType": "A股",                       # 必填：证券类型
    "FactorDeps": {"market_data": ["close"]},
    "DBDeps": {"JYDB": "聚源数据库"},
    "ModelArgs": {"short_window": "短期窗口", "long_window": "长期窗口"},
    "OperatorConfig": {"SignalType": "目标权重", "InitCash": 1e6, "ShortAllowed": False},
    "Author": "YourName",
    "Description": "均线交叉策略",
    "Tags": ["均线", "趋势"],
    "MaxLookBack": 120,
    "DefScriptPath": __file__,
}

# ---- 策略类 ----
class MACrossStrategy(MakeStrategy):
    def genSignal(self, f, idt, x, last_price, cash, position_num, args):
        short_ma, long_ma = x[0], x[1]
        if short_ma is None or long_ma is None:
            return None
        signal = pd.Series(0, index=short_ma.index)
        signal[short_ma > long_ma] = 1
        signal[short_ma < long_ma] = -1
        return signal

# ---- 入口函数 ----
def defStrategy(sdi: StrategyDefInput) -> list:
    """接收 StrategyDefInput，返回策略实例列表

    框架在调用前已完成:
    1. 递归解析 FactorDeps 和 StrategyDeps 依赖链
    2. 将依赖因子注入 sdi.Factors
    3. 将依赖策略注入 sdi.Strategies
    """
    close = sdi.Factors["close"]
    short_window = int(sdi.ModelArgs.get("short_window", 5))
    long_window = int(sdi.ModelArgs.get("long_window", 20))

    op = MACrossStrategy(
        signal_type="目标权重", init_cash=1e6, short_allowed=False,
        x_lookback=[short_window - 1, long_window - 1],
        x_section_ids=[None, None],
    )

    from QuantStudio.Factor import FactorOperator as fo
    ma_short = fo.RollingMean(window=short_window, min_periods=1)(close)
    ma_long = fo.RollingMean(window=long_window, min_periods=1)(close)

    return [op(ma_short, ma_long, last_price=close)]
```

## 核心概念

### 架构分层

```
策略定义模块 (业务代码)
    │  声明 __STRATEGY_META__，实现 defStrategy()
    ▼
StrategyDefContent (框架层)
    │  StrategyMeta / StrategyDef / build_dep_sd / StrategyDefInputBuilder
    ▼
run_strategy_def.py (执行层)
    │  解析配置 → 构建依赖图 → 调用 defStrategy → 写入因子表
    ▼
FactorStorer → Engine.run() (计算引擎)    AccountStats → BTStorer → HDF5BTResultDB (可选)
```

### 数据流

```
配置文件 (settings.py)
    → StrategyDefSettings
    → StrategyDefInputBuilder
        ├── resolve_dts()       → DTs, DTRuler
        ├── resolve_ids_for()   → IDs, SectionIDs
        ├── resolve_fdb()       → FDB dict
        └── _resolve_modules_for() → 模块列表
    → build_dep_sd(modules, sdi)
        ├── 收集所有 FactorDeps → build_dep_fd (统一解析因子依赖)
        ├── 递归解析 StrategyDeps → 调用依赖策略的 defStrategy
        ├── 注入 sdi.Factors / sdi.Strategies
        └── 调用目标 defStrategy → 包装为 StrategyDef
    → 按 TargetTable 分组 → FactorStorer → Engine.run()
    → 可选：AccountStats → BTStorer → HDF5BTResultDB (回测结果存储)
```

## __STRATEGY_META__ 字段参考

每个策略模块**必须**在顶部声明 `__STRATEGY_META__` 字典。

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `TargetTable` | `str` | **是** | — | 策略信号输出的因子表名。多个定义文件可共享同一 TargetTable，但同表内信号名必须唯一 |
| `IDType` | `str` | **是** | — | 证券类型，如 `"A股"`、`"ETF"`、`"期货"` |
| `OperatorConfig` | `dict` | 否 | `{"SignalType": "目标权重", "InitCash": 1e6, "ShortAllowed": False}` | 策略算子默认配置 |
| `FactorDeps` | `dict[str, list]` | 否 | `{}` | 依赖的因子定义模块及其因子名 |
| `StrategyDeps` | `dict[str, list]` | 否 | `{}` | 依赖的策略声明，key 为模块路径，value 为 `[{Name: 信号名, Alias: 别名, ModelArgs: {...}}]` |
| `DBDeps` | `dict[str, str]` | 否 | `{}` | 依赖的因子库，key 为 FDB 中的逻辑名称，value 为用途说明 |
| `ModelArgs` | `dict[str, str]` | 否 | `{}` | 可调参数声明，key 为参数名，value 为参数说明 |
| `Author` | `str` | 否 | `"Anonymous"` | 作者 |
| `Description` | `str` | 否 | `""` | 模块描述 |
| `MaxLookBack` | `int` | 否 | `365` | 最大回溯天数，框架会根据依赖链自动传播最大值 |
| `Tags` | `list[str]` | 否 | `[]` | 检索标签 |
| `DefScriptPath` | `str` | 否 | `""` | 脚本路径，建议设为 `__file__` |
| `ResultKey` | `str` | 否 | `None` | 回测结果存储路径模板，支持 `{IDType}`、`{TargetTable}`、`{StrategyName}` 占位符；为 None 时使用默认格式 `{IDType}/{TargetTable}/{StrategyName}` |

### FactorDeps 条目格式

```python
"FactorDeps": {
    "因子定义模块路径": [
        "因子名1",                                          # 字符串：直接引用
        {"Name": "因子名2", "Alias": "别名"},                # 字典：可指定别名
        {"Name": "因子名3", "ModelArgs": {"k": "v"}},       # 向依赖模块传递参数
        "*",                                                 # 通配：引用模块所有因子
    ],
}
```

- `Name` — 因子名（必填），`"*"` 表示该表全部因子
- `Alias` — 注入到 `fdi.Factors` 时的别名（可选，默认用 Name）
- `ModelArgs` — 传递给依赖模块 `defFactor` 的参数（可选），值以 `$` 开头时从父模块 `fdi.ModelArgs` 中查找

### StrategyDeps 条目格式

与 `FactorDeps` 对齐，value 为 list，每个元素为 str 或 dict：

```python
"StrategyDeps": {
    "依赖策略的模块路径": [
        {"Name": "信号因子名", "Alias": "本地别名"},       # 字典格式
        {"Name": "另一信号", "Alias": "别名2", "ModelArgs": {"lookback": 60}},  # 带参数
    ],
}
```

- `Name` — 信号因子名（必填）
- `Alias` — 注入到 `sdi.Strategies` 时的别名（可选，默认用 Name）
- `ModelArgs` — 传递给依赖模块 `defStrategy` 的参数（可选），值以 `$` 开头时从父模块 `sdi.ModelArgs` 中查找

依赖模块的 `defStrategy` 会先于当前模块被调用，其输出的信号因子通过 `sdi.Strategies["别名"]` 注入。

## defStrategy 函数规范

```python
def defStrategy(sdi: StrategyDefInput) -> list:
```

**返回值**：`List[Factor]` — 策略实例列表，一个模块可以定义多个策略。框架自动将列表中的每个策略实例包装为 `StrategyDef` 对象。

> **向后兼容**：框架同时兼容返回单个 `Factor`（旧格式），内部会自动包装为单元素列表。

### StrategyDefInput 字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `sdi.Debug` | `bool` | 是否调试模式 |
| `sdi.FDB` | `dict[str, FactorDB]` | 可用因子库字典 |
| `sdi.ModelArgs` | `dict` | 参数覆盖值（来自配置文件的 `model_args`） |
| `sdi.DTs` | `list[datetime]` | 计算时点列表 |
| `sdi.DTRuler` | `list[datetime]` | 时点标尺（更长的时间范围，用于回溯计算） |
| `sdi.IDs` | `list[str]` | 证券 ID 列表 |
| `sdi.SectionIDs` | `list[str]` | 截面 ID 列表 |
| `sdi.TDB` | `WritableFactorDB` | 目标写入因子库 |
| `sdi.Factors` | `dict[str, Factor]` | **已解析的依赖因子**（框架注入） |
| `sdi.Strategies` | `dict[str, Factor]` | **已解析的依赖策略信号**（框架注入） |

## 策略编写模式

### 单策略模块

最常见的模式——模块返回一个策略实例：

```python
def defStrategy(sdi: StrategyDefInput) -> list:
    close = sdi.Factors["close"]
    op = MyStrategy(signal_type="目标权重", init_cash=1e6, short_allowed=False)
    return [op(close)]
```

### 多策略模块

一个模块返回多个策略实例，共享相同的元信息和依赖：

```python
def defStrategy(sdi: StrategyDefInput) -> list:
    close = sdi.Factors["close"]

    # 策略 1：短期均线
    op1 = MAStrategy(signal_type="目标权重", init_cash=1e6, short_allowed=False,
                     x_lookback=[4, 19], x_section_ids=[None, None])
    signal1 = op1(fo.RollingMean(window=5, min_periods=1)(close),
                  fo.RollingMean(window=20, min_periods=1)(close))

    # 策略 2：动量策略
    op2 = MomentumStrategy(signal_type="目标权重", init_cash=1e6, short_allowed=False)
    signal2 = op2(close)

    return [signal1, signal2]
```

框架为每个策略实例创建独立的 `StrategyDef`，存储在 `dep_sd` 中。单策略时 key 为 `DefKey`，多策略时 key 为 `DefKey/策略名`。

### 依赖其他策略

通过 `StrategyDeps` 声明对其他策略模块输出的依赖：

```python
__STRATEGY_META__ = {
    "TargetTable": "composite_signals",
    "IDType": "A股",
    "StrategyDeps": {
        "my_strategies.ma_cross": [
            {"Name": "ma_signal", "Alias": "ma"},         # 引用 ma_cross 模块输出的 ma_signal，别名为 ma
        ],
        "my_strategies.momentum": [
            {"Name": "mom_signal", "Alias": "mom"},
        ],
    },
}

def defStrategy(sdi: StrategyDefInput) -> list:
    ma_signal = sdi.Strategies["ma"]    # 依赖策略的信号因子
    mom_signal = sdi.Strategies["mom"]
    # 组合信号...
```

### 向依赖策略传递参数

在 `StrategyDeps` 的条目中通过 `ModelArgs` 字段向依赖模块传递参数，与 FactorDef 的 `$` 语法对齐：

```python
__STRATEGY_META__ = {
    "StrategyDeps": {
        "my_strategies.ma_cross": [
            {"Name": "ma_signal", "Alias": "ma", "ModelArgs": {"lookback": 60}},       # 直接传值
            {"Name": "vol_signal", "Alias": "vol", "ModelArgs": {"window": "$parent_w"}},  # $ 从父模块取值
        ],
    },
}
```

- `"lookback": 60` — 直接传值，依赖模块的 `sdi.ModelArgs["lookback"]` 为 `60`
- `"$parent_w"` — 以 `$` 开头时，从父模块的 `sdi.ModelArgs["parent_w"]` 查找并透传

### 参数透传

`$` 前缀语法用于从父模块向依赖模块透传参数，FactorDeps 和 StrategyDeps 中均可使用：

```python
# 子模块
__STRATEGY_META__ = {
    "ModelArgs": {"lookback": "回溯天数"},  # 声明期望的模型参数
}

def defStrategy(sdi: StrategyDefInput) -> list:
    lookback = sdi.ModelArgs["lookback"]  # 框架已从父模块透传注入
    ...

# 父模块
__STRATEGY_META__ = {
    "ModelArgs": {"parent_lookback": "父模块的回溯天数"},
    "FactorDeps": {
        "market_data": [
            {"Name": "close", "ModelArgs": {"lookback": "$parent_lookback"}},  # $ 引用
        ],
    },
    "StrategyDeps": {
        "my_strategies.ma_cross": [
            {"Name": "ma_signal", "Alias": "ma", "ModelArgs": {"window": "$parent_lookback"}},
        ],
    },
}
```

当 `defStrategy` 被调用时，`sdi.ModelArgs` 已包含父模块透传的参数，子模块不需要知道参数来源。

### Notebook 策略定义

除 `.py` 文件外，框架也支持 `.ipynb` notebook 作为策略定义载体。与 `.py` 文件的区别在于：
- **选择性执行**：通过 Jupyter cell tag 标记策略定义 cell，框架只执行带 tag 的 cell
- **自足构建**：直接在 cell 中构建策略对象，不依赖 `defStrategy(sdi)` 注入

#### 协议约定

在 notebook 中对策略核心 cell 打 `strategy-def` tag。框架找到**最后一个**带此 tag 的 cell，执行该 cell 及其之前的所有 code cell。若执行失败则回退执行所有 code cell。

典型结构：

```
Cell 0: [strategy-def] import + __STRATEGY_META__ + MakeStrategy 子类
Cell 1: [strategy-def] 参数 + 数据库连接 + 因子构建 + 策略对象构建
Cell 2: [无 tag] 交互式调试/可视化（框架不执行）
```

框架从执行结果中收集 `Operator` 为 `MakeAccount` 实例的因子作为策略输出。

#### Notebook 示例

```python
# Cell 0: [strategy-def]
import pandas as pd
from QuantStudio.Factor import FactorOperator as fo
from QuantStudio.Factor.HDF5DB import HDF5DB
from QuantStudio.BackTest.Strategy.Strategy import MakeStrategy, MakeAccount

__STRATEGY_META__ = {
    "TargetTable": "strategy_signals",
    "IDType": "A股",
    "DBDeps": {"HDF5DB": "行情数据"},
    ...
}

class MACrossStrategy(MakeStrategy):
    def genSignal(self, f, idt, x, last_price, cash, position_num, args):
        short_ma, long_ma = x[0], x[1]
        if short_ma is None or long_ma is None:
            return None
        signal = pd.Series(0, index=short_ma.index)
        signal[short_ma > long_ma] = 1
        signal[short_ma < long_ma] = -1
        return signal

# Cell 1: [strategy-def]
HDB = HDF5DB(args={"MainDir": r"D:\Data\HDF5DB"}).connect()
FT = HDB.getTable("stock_cn_day_bar_nafilled")
close = FT.getFactor("close")
ma_short = fo.RollingMean(window=5, min_periods=1)(close)
ma_long = fo.RollingMean(window=20, min_periods=1)(close)

makeStrategy = MACrossStrategy(
    signal_type="目标权重", init_cash=1e6, short_allowed=False,
    x_lookback=[4, 19], x_section_ids=[None, None],
)
Account = makeStrategy(ma_short, ma_long, last_price=close)
```

## 回测结果存储

配置 `BT_STORE` 后，流水线会在写入策略信号因子的同时，自动构建 `AccountStats → BTStorer` 节点链，将回测结果（净值曲线、统计数据、交易记录等）持久化到 `HDF5BTResultDB`。

### 配置方式

```python
# settings.py
BT_STORE = {
    "name": "BTResultDB",
    "class": "HDF5BTResultDB",
    "args": {"MainDir": r"D:\Data\BTResult"},
}
```

格式与 `FACTOR_DATABASES` 单项一致，支持 `name`、`class`、`args`、`config_file` 字段。

> **启用/禁用**：`BT_STORE` 即为开关——配置了就存储回测结果，注释掉或设为 `None` 则不存储。流水线中通过 `settings.bt_store is None` 判断是否跳过 `AccountStats → BTStorer` 节点的构建。

### GroupName 生成

每个策略的回测结果以 GroupName 作为存储路径，映射为 HDF5 目录结构：

| ResultKey | IDType | TargetTable | StrategyName | GroupName |
|-----------|--------|-------------|--------------|-----------|
| 未设置 | A股 | strategy_signals | MACrossStrategy | `A股/strategy_signals/MACrossStrategy` |
| `"{TargetTable}/{StrategyName}"` | A股 | strategy_signals | MACrossStrategy | `strategy_signals/MACrossStrategy` |
| `"行业轮动/{StrategyName}"` | A股 | strategy_signals | MACrossStrategy | `行业轮动/MACrossStrategy` |

可通过 `__STRATEGY_META__["ResultKey"]` 自定义格式，支持 `{IDType}`、`{TargetTable}`、`{StrategyName}` 占位符。

### 存储内容

每个 GroupName 对应一个 `.h5` 文件，包含 `AccountStats.backward_compute()` 的完整输出：

- **时间序列**：净值、收益率、累计收益率等
- **统计数据**：年化收益、最大回撤、夏普比率等
- **交易记录**：交易时点、ID、交易量、成交价、交易费
- **交易信号**：每日信号值
- **持仓数量**：每日持仓

HDF5 文件的 `attrs` 中存储从 `__STRATEGY_META__` 提取的元信息（IDType、Description、Author、Tags 等），支持通过 `BTResultDB.listResults(metadata={...})` 按标签筛选。

## 与 FactorDef 的对比

| 维度 | FactorDef | StrategyDef |
|------|-----------|-------------|
| 入口函数 | `defFactor(fdi) -> list` | `defStrategy(sdi) -> list` |
| 输入类型 | `FactorDefInput` | `StrategyDefInput`（额外增加 `Strategies` 字段） |
| 输出类型 | `FactorDef` 包装 | `StrategyDef` 包装 |
| 元信息类 | `FactorMeta` | `StrategyMeta`（额外增加 `OperatorConfig`/`StrategyDeps`/`ResultKey`） |
| 配置类 | `FactorDefSettings` | `StrategyDefSettings`（额外增加 `BT_STORE`） |
| 连接池 | `FactorDBPool` | `StrategyDBPool` |
| 策略间依赖 | 不支持 | 通过 `StrategyDeps` 支持 |
| 回测结果存储 | 不支持 | 通过 `BT_STORE` + `BTStorer` 支持 |
