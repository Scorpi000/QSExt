## 二、设计目标

让 假设生成阶段能够**系统性地利用历史经验**：

```
假设生成阶段 Agent
    │
    ├── 1. "这个方向之前试过吗？结果怎样？" → search_by_direction()
    ├── 2. "有没有类似的成功案例可以参考？" → search_similar_accepted() [语义]
    ├── 3. "这个方向有什么失败教训？" → get_failed_directions()
    ├── 4. "有哪些可复用的组件？" → get_successful_patterns()
    ├── 5. "当前方向的高频代码模式是什么？" → get_frequent_patterns()
    └── 6. "哪些方向还没探索过？" → get_direction_coverage()
```

## 三、实现计划

### 3.1 向量语义检索（P0）✅

**状态**：已实现（2026-07-07）

**改动文件**：`retriever.py`、`repository.py`、`models.py`

**实际实现**：

1. **`Experience` 模型新增 `embedding_str` 字段**（`MiningRun` 已有），`to_db_row()` 支持 embedding 写入。

2. **`MiningLogRepository` 自动写入 embedding**：构造函数接受可选 `EmbeddingService`，`insert_run()` / `insert_experience()` 在有 content 且无 embedding 时自动生成。ON CONFLICT upsert 也包含 embedding 字段更新。

3. **`MiningLogRepository` 新增向量检索方法**：
   - `search_mining_log_by_embedding(embedding_str, top_k, score_threshold)` → `list[(MiningRun, float)]`
   - `search_experience_by_embedding(embedding_str, top_k, score_threshold, track)` → `list[(Experience, float)]`
   - `backfill_embeddings(table, batch_size)` → 为历史记录补写 embedding

4. **`MiningLogRetriever` 新增语义检索方法**：
   - `search_by_embedding(query, table, top_k, score_threshold, track)` — 通用语义搜索
   - `search_similar_accepted(query, top_k, score_threshold)` — 语义搜索 accepted 记录（供 few-shot）
   - `get_similar_failures(query, top_k, score_threshold)` — 语义搜索失败经验（供规避）

**使用示例**：

```python
from QSExt.LLMFactor.llm.mining_log import (
    MiningLogDB, MiningLogRepository, MiningLogRetriever, EmbeddingService,
)

db = MiningLogDB()
db.init_tables()
emb = EmbeddingService()
repo = MiningLogRepository(db, embedding_service=emb)
retriever = MiningLogRetriever(repo, embedding_service=emb)

# 入库时自动生成 embedding
repo.insert_run(run)

# 语义检索
results = retriever.search_by_embedding("日内动量 方向预测")
# → [(RunSummary, 0.82), (RunSummary, 0.75), ...]

# 语义搜索 accepted（供 few-shot）
accepted = retriever.search_similar_accepted("动量因子")

# 语义搜索失败经验（供规避）
failures = retriever.get_similar_failures("IC 很低的因子")

# 补写历史记录
repo.backfill_embeddings(table="mining_log", batch_size=100)
```

**测试**：`tests/test_retriever_embedding.py`（24 用例：11 单元 + 13 集成）

### 3.2 LLM 审查器接入（P1）✅

**状态**：已实现（2026-07-07）

**改动文件**：新增 `llm_reviewer.py`、`llm_client.py`

**架构**：基于 LangChain 统一接口，通过工厂模式支持多 LLM 后端：

```
LLMReviewer(llm: BaseChatModel)
    │
    ├── create_llm("ollama")   → ChatOllama（本地 Ollama）
    └── create_llm("openai")   → ChatOpenAI（OpenAI 兼容：DeepSeek/千问/智谱/MIMO 等）
```

**`llm_client.py` — LLM 工厂**：

```python
from QSExt.LLMFactor.llm.mining_log.llm_client import create_llm

# 本地 Ollama
llm = create_llm("ollama", model="qwen3")

# 外部 LLM（OpenAI 兼容）
llm = create_llm("openai", model="deepseek-chat",
    base_url="https://api.deepseek.com/v1", api_key="sk-xxx")

# 从 .env 自动读取配置（LLM_PROVIDER / LLM_BASE_URL / LLM_API_KEY / LLM_MODEL）
llm = create_llm()
```

**`.env` 配置**：

```bash
# 切换 LLM 提供商
LLM_PROVIDER=openai              # ollama 或 openai

# Ollama 本地
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_LLM_MODEL=qwen3

# 外部 LLM（OpenAI 兼容接口）
LLM_BASE_URL=https://token-plan-cn.xiaomimimo.com/v1
LLM_API_KEY=tp-xxx
LLM_MODEL=mimo-v2.5-pro
LLM_TIMEOUT=120
```

**`llm_reviewer.py` — 审查器**：

```python
from QSExt.LLMFactor.llm.mining_log.llm_reviewer import LLMReviewer

# 使用默认配置（从 .env 读取）
reviewer = LLMReviewer()

# 注入指定 LLM
reviewer = LLMReviewer(llm=create_llm("openai", model="mimo-v2.5-pro"))

# 组件审查
result = reviewer.review_component(code_snippet, name, description)
# → {"approved": bool, "financial_rationale": str, "issues": [], "quality_score": float}

# 失败分类
result = reviewer.classify_failure(run)
# → {"failure_type": str, "lesson_learned": str, "recovery_strategy": str}
```

**关键设计**：
- `_extract_json()` 健壮提取 LLM 输出中的 JSON（支持纯 JSON / markdown 代码块 / 周围有文字 / `<think>` 标签）
- 错误回退：LLM 调用失败时自动降级到与 `NoOpReviewer` 相同的规则判断，不阻断流程
- 通过 `SystemMessage` + `HumanMessage` 结构化调用，temperature=0.1 保证输出稳定

**集成方式**：

```python
from QSExt.LLMFactor.llm.mining_log import LLMReviewer, ExperienceRefiner

reviewer = LLMReviewer()  # 使用 .env 中的 LLM_PROVIDER 配置
refiner = ExperienceRefiner(repo, reviewer=reviewer)
experiences = refiner.refine(run)
```

**测试**：`tests/test_llm_reviewer.py`（23 用例：19 单元 + 4 集成，含 MIMO API 实测）

### 3.3 AST 代码结构分析（P2）

**目标**：用 Python AST 解析因子代码，提取算子调用图结构，实现真正的频繁子图挖掘。

**改动文件**：新增 `code_analyzer.py`，修改 `retriever.py`

**实现**：

```python
import ast

class FactorCodeAnalyzer:
    """因子代码结构分析器。"""

    def extract_operator_calls(self, code: str) -> list[dict]:
        """从因子代码中提取算子调用序列。

        Returns:
            [{"operator": "fo.Where", "args": [...], "line": 10}, ...]
        """

    def extract_dag_structure(self, code: str) -> dict:
        """提取因子的计算 DAG 结构。

        Returns:
            {"nodes": ["open", "close", "intraday_ret"],
             "edges": [("open", "intraday_ret"), ("close", "intraday_ret")],
             "operators": ["fo.SectionRank", "fo.RollingMean"]}
        """

    def compute_pattern_signature(self, code: str) -> str:
        """计算代码的结构签名（用于模式匹配）。

        将具体变量名抽象化，保留算子调用序列和 DAG 拓扑。
        例如："{fo.RollingMean}({fo.Lag}({raw}))" 
        """
```

**频繁模式统计**：

```python
def update_frequent_patterns(repo: MiningLogRepository, top_k: int = 10):
    """从所有入库因子中统计 top-k 频繁代码结构。"""
    accepted_runs = repo.get_accepted_runs(limit=1000)
    pattern_counts = Counter()
    for run in accepted_runs:
        code = run.metadata.get("development", {}).get("code", "")
        if code:
            sig = analyzer.compute_pattern_signature(code)
            pattern_counts[sig] += 1
    return pattern_counts.most_common(top_k)
```

**存储**：结果写入 `mining_experience` 表，`track=success`, `type=formula_pattern`。

### 3.4 方向索引管理（P2）

**目标**：持久化各方向的探索状态（探索次数、成功率、冻结状态），支持 假设生成阶段 的搜索预算分配。

**改动文件**：新增 `direction_index.py`

**数据结构**：

```python
@dataclass
class DirectionEntry:
    direction_tag: str          # "动量/日内方向预测"
    attempts: int               # 总尝试次数
    successes: int              # 成功次数
    failures: int               # 失败次数
    frozen: bool                # 是否冻结
    frozen_reason: str          # 冻结原因
    last_attempt_at: str        # 最近尝试时间
    best_rankic: float          # 该方向历史最高 RankIC
    best_run_id: str            # 最高 RankIC 的运行 ID
```

**存储**：复用 `mining_experience` 表，`track=meta`, `type=direction_index`。

**接口**：

```python
class DirectionIndex:
    def get(self, direction_tag: str) -> Optional[DirectionEntry]
    def update(self, run: MiningRun):  # 根据 run 结果更新方向统计
    def freeze(self, direction_tag: str, reason: str)
    def unfreeze(self, direction_tag: str)
    def get_all(self) -> list[DirectionEntry]
    def get_frozen(self) -> list[DirectionEntry]
    def get_high_potential(self, min_attempts: int = 3) -> list[DirectionEntry]
        # 高潜力 = 成功率高但探索次数少
```

**自动更新**：在 `ExperienceRefiner.refine()` 末尾调用 `DirectionIndex.update(run)`。

### 3.5 经验使用追踪（P2）

**目标**：当 假设生成阶段 检索到某条经验并用于假设生成时，递增其 `usage_count`。

**改动文件**：`retriever.py`

**实现**：

```python
# 在 MiningLogRetriever 中
def mark_used(self, experience_id: str):
    """标记经验被使用，递增 usage_count。"""
    self._repo.increment_usage(experience_id)
```

**调用时机**：假设生成阶段 Agent 引用某条经验后，调用 `mark_used()`。
