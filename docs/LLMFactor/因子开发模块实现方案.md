## 1. 概述

### 1.1 定位

因子开发阶段 是因子挖掘流水线的核心缺失环节，连接 假设生成阶段（假设生成）和 因子评测阶段（因子评测）。目标是将 假设生成阶段 输出的结构化假设文档（`HypothesisDoc`）转化为 QuantStudio 框架下可执行、可验证的因子代码，并通过贝叶斯参数搜索找到最优超参数。

### 1.2 核心设计：宏微观分离

借鉴 `macro-micro-co-evolution` 的三层分离原则：

| 层次 | 负责方 | 任务 | 调用频率 | LLM 参与 |
|------|--------|------|----------|----------|
| **宏观层** | LLM Agent | 因子逻辑设计、算子选择、DAG 结构编排、代码生成 | 每次假设 1-3 次 | Yes |
| **微观层** | Optuna/TPE | 超参数搜索（窗口大小、衰减因子、阈值） | 每次假设数百次 | No |
| **验证层** | 确定性脚本 + LLM | 语法检查、执行验证、未来信息泄漏检测、单位检查、语义审查 | 每次代码变更 | 部分 |

**核心论点**：LLM 擅长语义推理和逻辑创新（高层次、小批量），但单个生成-评估周期耗时长；参数优化适合自动化搜索（低层次、大批量），需要大量评估迭代。将两者耦合会导致 LLM 等待回测结果、计算资源闲置。

### 1.3 开发原则

1. **代码空间表达**：LLM 直接生成完整的 Pandas/NumPy 因子函数代码（非固定表达式树），可表达条件逻辑、状态切换、非对称衰减等复杂构造
2. **框架合规**：严格遵循 QuantStudio FactorDef 规范（`defFactor(fdi) -> List[Factor]` 模式）
3. **防泄漏设计**：财务数据使用 `CalcType="最新"`（公告时点）；LLM 不接触原始数据值
4. **双板合并**：A 股因子必须同时覆盖主板和科创板，使用 `fo.Where + fo.NotNull` 合并策略
5. **可执行即正确**：代码必须能通过 Python 导入和执行，无语法错误、无运行时异常

### 4.1.1 自定义目标与指标扩展

#### 评估指标体系

`EvalMetrics` 分为两层：**内置指标**（由 ParamSearcher 自动计算）和 **扩展指标**（由用户自定义 MetricCalculator 计算）。两者合并后统一传递给目标函数。

```python
@dataclass
class EvalMetrics:
    """因子评估指标集合。

    内置指标由 ParamSearcher 自动计算，扩展指标由用户的 MetricCalculator 追加。
    所有指标均可在自定义目标函数中通过属性访问。
    """
    # ---- 内置指标（自动计算） ----
    rankic: float = 0.0             # Rank IC 均值
    icir: float = 0.0               # IC 信息比率
    win_rate: float = 0.0           # IC 胜率
    max_drawdown: float = 0.0       # 最大回撤
    turnover: float = 0.0           # 换手率

    # ---- 扩展指标（用户追加） ----
    extra: dict = field(default_factory=dict)

    def __getattr__(self, name: str):
        """支持通过属性访问扩展指标。"""
        extra = object.__getattribute__(self, "extra")
        if name in extra:
            return extra[name]
        raise AttributeError(f"EvalMetrics 没有指标 '{name}'")
```

#### MetricCalculator 接口

用户实现此协议来计算自定义指标。ParamSearcher 在每次试验后调用所有注册的计算器，将结果合并到 `EvalMetrics.extra` 中。

```python
from typing import Protocol, runtime_checkable

@runtime_checkable
class MetricCalculator(Protocol):
    """自定义指标计算器协议。

    用户实现此协议来扩展评估指标。每次参数试验时，
    ParamSearcher 会调用 calculator() 方法，返回的指标
    合并到 EvalMetrics.extra 中，供目标函数使用。

    示例::

        class SectorNeutralICCalculator:
            \"\"\"行业中性 IC 计算器。\"\"\"
            def __init__(self, industry_factor):
                self.industry_factor = industry_factor

            def calculator(self, factor, price, fdi, params) -> dict:
                # 计算行业中性化后的 IC
                neutral_ic = calc_neutralized_ic(factor, price, self.industry_factor, fdi)
                return {"sector_neutral_ic": neutral_ic}

        config = DevelopmentConfig(
            custom_metric_calculators=[SectorNeutralICCalculator(industry_factor)],
            optimization_objective="custom",
            custom_objective_fn=lambda m, p: m.sector_neutral_ic * 0.6 + m.rankic * 0.4,
        )
    """
    def calculator(self, factor: Any, price: Any, fdi: Any, params: dict) -> dict:

            params: 当前试验的超参数

            指标名到值的映射，如 {"sector_neutral_ic": 0.035, "decay_half_life": 12}
        """
        ...
```

## 5. Step 1: 代码生成

### 5.1 CodeGenerator 类

```python
class CodeGenerator:
    """因子代码生成器。"""
    
    def __init__(self, config: DevelopmentConfig):
        self.config = config
        self.llm = create_llm(model=config.llm_model, temperature=config.llm_temperature)
        self.retriever = MiningLogRetriever()  # 经验检索
    
    def generate(self, hypothesis: dict) -> GeneratedCode:
        """从假设文档生成因子代码。
        
        Args:
            hypothesis: HypothesisDoc.to_development_input() 的输出
            
        Returns:
            GeneratedCode 包含代码、搜索空间、元数据
        """
        # 1. 检索相关经验组件
        components = self._retrieve_relevant_components(hypothesis)
        
        # 2. 获取参考因子代码
        ref_codes = self._get_reference_codes(hypothesis)
        
        # 3. 构建 prompt
        prompt = self._build_generation_prompt(hypothesis, components, ref_codes)
        
        # 4. LLM 生成
        response = self.llm.invoke(prompt)
        
        # 5. 解析输出
        return self._parse_response(response, hypothesis)
    
    def fix(self, code: str, hypothesis: dict, failures: list) -> str:
        """根据验证失败报告修复代码。
        
        Args:
            code: 当前因子代码
            hypothesis: 原始假设文档
            failures: 失败的验证报告列表
            
        Returns:
            修复后的代码
        """
        prompt = self._build_fix_prompt(code, hypothesis, failures)
        response = self.llm.invoke(prompt)
        return self._extract_code(response)
```

### 5.2 经验引用策略

通过 `MiningLogRetriever` 检索相关经验：

```python
def _retrieve_relevant_components(self, hypothesis: dict) -> list[dict]:
    """检索与当前假设相关的成功组件。"""
    category = hypothesis.get("category", "")
    description = hypothesis.get("factor_description", "")
    
    # 按类别检索成功组件
    components = self.retriever.get_successful_components(
        domain="logic_component",
        direction=category,
        min_quality=0.7,
        limit=5,
    )
    
    # 按相似性检索
    similar = self.retriever.search_similar_accepted(
        query=f"{category} {description}",
        limit=3,
    )
    
    return components + similar
```

### 5.4 DAG 任务分解

LLM 在生成代码前，先进行 DAG 分解：

1. 列出所有计算步骤
2. 确定每个步骤的输入依赖
3. 构建有向无环图
4. 按拓扑排序确定执行顺序
5. 为每个节点选择合适的算子类型

这一步隐含在 prompt 中，通过要求 LLM 先输出"计算步骤分解"再输出代码来实现。

```python
class VerificationPipeline:
    """五 Agent 验证流水线。"""
    
    def __init__(self, config: DevelopmentConfig):
        self.validators = [
            SyntaxValidator(),      # Agent A（始终启用）
            ExecutionValidator(),   # Agent B（始终启用）
        ]
        if config.enable_leak_test:
            self.validators.append(LeakValidator())      # Agent C（可选）
        if config.enable_unit_check:
            self.validators.append(UnitValidator())       # Agent D（可选）
        if config.enable_semantic_review:
            self.validators.append(SemanticValidator(config))  # Agent E（可选，LLM）
    
    def run_all(self, factor_dir: str, hypothesis: dict) -> ValidationReport:
        """运行所有验证器。"""
        results = []
        for validator in self.validators:
            result = validator.validate(factor_dir, hypothesis)
            results.append(result)
        
        all_passed = all(r.passed for r in results)
        return ValidationReport(
            syntax=results[0],
            execution=results[1],
            leak_test=results[2],
            unit_check=results[3],
            semantic_review=results[4],
            auto_fix_count=0,
            all_passed=all_passed,
        )
```

```python
        issues = []
        
        try:
            # 1. 动态导入
            factor_obj = FactorObject(factor_dir)

                issues.append("defFactor() 返回空列表")
                return ExecutionReport(passed=False, output_shape=None, nan_ratio=1.0, issues=issues)
            
            # 4. readData() 小样本运行
            factor = factors[0]
            data = factor.readData(
                ids=fdi.IDs[:10],
                dts=fdi.DTs[:20],
                section_ids=fdi.SectionIDs,
                dt_ruler=fdi.DTRuler,
            )
            
            # 5. 输出验证
            if data.size == 0:
                issues.append("readData() 返回空数据")
            
            nan_ratio = np.isnan(data.values).sum() / data.size if data.size > 0 else 1.0
            if nan_ratio > 0.5:
                issues.append(f"NaN 比例过高: {nan_ratio:.1%}")
            
            return ExecutionReport(
                passed=len(issues) == 0,
                output_shape=data.shape if data.size > 0 else None,
                nan_ratio=nan_ratio,
                issues=issues,
            )
        except Exception as e:
            issues.append(f"执行异常: {e}")
            return ExecutionReport(passed=False, output_shape=None, nan_ratio=1.0, issues=issues)
```

```python
            return LeakTestReport(
                passed=True,
                test_dates=[],
                max_diff=0.0,
                correlation=1.0,
                method="财务数据使用 CalcType='最新'(公告时点) 天然防泄漏，无需时序截断测试",
                issues=[],
            )
        
        # 时序截断单元测试
        factor_obj = FactorObject(factor_dir)
        fdi = self._build_test_fdi()
        factors = factor_obj.replay(fdi)
        factor = factors[0]
        
        # 随机抽取测试日期
        test_dates = self._sample_test_dates(fdi.DTs, n=10)
        
        max_diff = 0.0
        min_corr = 1.0
        for dt in test_dates:
            # 截断数据至 dt
            truncated_dts = [d for d in fdi.DTRuler if d <= dt]
            truncated_fdi = self._truncate_fdi(fdi, truncated_dts)
            
            # 使用截断数据重算
            truncated_factors = factor_obj.replay(truncated_fdi)
            truncated_data = truncated_factors[0].readData(...)
            
            # 比较
            original_data = factor.readData(...)
            diff = abs(original_data - truncated_data).max()
            corr = original_data.corr(truncated_data)
            
            max_diff = max(max_diff, diff)
            min_corr = min(min_corr, corr)
        
        passed = max_diff < 1e-8 and min_corr > 0.9999
        
        return LeakTestReport(
            passed=passed,
            test_dates=[str(d) for d in test_dates],
            max_diff=max_diff,
            correlation=min_corr,
            method="时序截断单元测试",
            issues=[] if passed else [f"疑似未来信息泄漏: max_diff={max_diff}, min_corr={min_corr}"],
        )
```

### 6.7 自动修复循环

修复失败时记录状态和原因，供后续分析和人工介入参考。

```python
@dataclass
class FixAttempt:
    """单次修复尝试记录。"""
    attempt: int                      # 第几次尝试
    timestamp: str                    # 时间戳
    failed_validators: list[str]      # 失败的验证器名称
    failure_reasons: list[str]        # 各验证器的失败原因摘要
    fix_applied: bool                 # 是否成功生成修复代码
    fix_description: str              # 修复动作描述
    result_status: str                # "passed" / "failed" / "needs_manual"

def develop_factor_with_fix(hypothesis: dict, config: DevelopmentConfig) -> DevelopmentResult:
    """带自动修复的因子开发流程。"""
    workspace = WorkspaceManager()
    ws_dir = workspace.create_workspace(hypothesis["factor_name"])
    fix_history: list[FixAttempt] = []

    # Step 1: 代码生成
    generator = CodeGenerator(config)
    generated = generator.generate(hypothesis)

    # 保存初始代码
    workspace.save_factor_code(ws_dir, generated.factor_code, generated.factor_module_name)
    workspace.save_metadata(ws_dir, generated.metadata)
    workspace.save_search_space(ws_dir, generated.search_space)

    # Step 2: 验证 + 修复循环
    verifier = VerificationPipeline(config)
    for attempt in range(config.max_auto_fixes + 1):
        report = verifier.run_all(str(ws_dir), hypothesis)

        if report.all_passed:
            fix_history.append(FixAttempt(
                attempt=attempt, timestamp=now(),
                failed_validators=[], failure_reasons=[],
                fix_applied=False, fix_description="全部通过",
                result_status="passed",
            ))
            break

        # 收集失败信息
        failed_names, failure_reasons = [], []
        for name, result in verifier.get_results(report):
            if not result.passed:
                failed_names.append(name)
                failure_reasons.append(f"{name}: {'; '.join(result.issues)}")

        if attempt < config.max_auto_fixes:
            # 自动修复
            fixed_code = generator.fix(
                code=ws_dir.read_text(f"{generated.factor_module_name}.py"),
                hypothesis=hypothesis,
                failures=report.get_failed_validators(),
            )
            workspace.save_factor_code(ws_dir, fixed_code, generated.factor_module_name)
            fix_history.append(FixAttempt(
                attempt=attempt, timestamp=now(),
                failed_validators=failed_names, failure_reasons=failure_reasons,
                fix_applied=True, fix_description=f"修复 {', '.join(failed_names)}",
                result_status="retried",
            ))
        else:
            # 超过最大修复次数，记录为需人工介入
            fix_history.append(FixAttempt(
                attempt=attempt, timestamp=now(),
                failed_validators=failed_names, failure_reasons=failure_reasons,
                fix_applied=False, fix_description="超过最大修复次数",
                result_status="needs_manual",
            ))

    report.auto_fix_count = attempt
    report.fix_history = fix_history
    workspace.save_validation_report(ws_dir, report)

    # Step 3: 参数搜索（仅验证通过时）
    if report.all_passed and generated.search_space:
        searcher = ParamSearcher(config)
        search_result = searcher.search(str(ws_dir), generated.search_space)
        workspace.save_search_result(ws_dir, search_result)
    else:
        search_result = SearchResult(best_params={}, best_rankic=0.0, ...)

    return DevelopmentResult(
        factor_dir=str(ws_dir),
        factor_code_path=str(ws_dir / f"{generated.factor_module_name}.py"),
        validation=report,
        search_result=search_result,
        factor_object=FactorObject(str(ws_dir)),
    )
```

## 7. Step 3: 参数搜索

### 7.1 ParamSearcher 类

支持四种优化目标模式：
- `"rankic"`（默认）：单目标，最大化 RankIC
- `"icir"`：单目标，最大化 ICIR
- `"multi"`：多目标，按 `multi_objective_weights` 加权组合
- `"custom"`：用户自定义，通过 `custom_objective_fn` 注入目标函数

```python
class ParamSearcher:
    """Optuna 贝叶斯参数搜索器。"""

    def __init__(self, config: DevelopmentConfig):
        self.config = config

    def search(self, factor_dir: str, search_space: dict) -> SearchResult:
        """搜索最优参数。

        Args:
            factor_dir: 因子目录路径
            search_space: 搜索空间定义

        Returns:
            SearchResult 包含最优参数和搜索历史
        """
        if not search_space:
            return SearchResult(
                best_params={}, best_rankic=0.0,
                optimization_history=pd.DataFrame(), sensitivity={},
            )

        factor_obj = FactorObject(factor_dir)
        objective_mode = self.config.optimization_objective

        # 创建 Optuna study
        if objective_mode == "multi" and self.config.multi_objective_weights:
            # 多目标优化：使用加权求和转化为单目标
            study = optuna.create_study(
                direction="maximize",
                sampler=TPESampler(seed=42),
                pruner=MedianPruner(n_warmup_steps=self.config.early_stop_rounds),
            )
        else:
            study = optuna.create_study(
                direction="maximize",
                sampler=TPESampler(seed=42),
                pruner=MedianPruner(n_warmup_steps=self.config.early_stop_rounds),
            )

        # 定义目标函数
        def objective(trial):
            params = {}
            for name, spec in search_space.items():
                if spec["type"] == "int":
                    params[name] = trial.suggest_int(
                        name, spec["low"], spec["high"], step=spec.get("step", 1)
                    )
                elif spec["type"] == "float":
                    params[name] = trial.suggest_float(
                        name, spec["low"], spec["high"]
                    )

            # 评估参数
            metrics = self._evaluate_params(factor_obj, params)

            if objective_mode == "rankic":
                return metrics["rankic"]
            elif objective_mode == "icir":
                return metrics["icir"]
            elif objective_mode == "multi":
                weights = self.config.multi_objective_weights or {"rankic": 1.0}
                return sum(metrics.get(k, 0.0) * v for k, v in weights.items())
            elif objective_mode == "custom":
                custom_fn = self.config.custom_objective_fn
                if custom_fn is None:
                    raise ValueError("optimization_objective='custom' 时必须提供 custom_objective_fn")
                # 将 metrics dict 包装为具有属性访问的对象
                metrics_obj = SimpleNamespace(**metrics)
                return custom_fn(metrics_obj, params)
            else:
                return metrics["rankic"]

        # 运行搜索
        study.optimize(
            objective,
            n_trials=self.config.max_trials,
            timeout=self.config.timeout,
        )

        # 计算参数敏感性
        sensitivity = self._calc_sensitivity(study, search_space)

        return SearchResult(
            best_params=study.best_params,
            best_rankic=study.best_value,
            optimization_history=study.trials_dataframe(),
            sensitivity=sensitivity,
        )

    def _evaluate_params(self, factor_obj: FactorObject, params: dict) -> dict:
        """使用给定参数评估因子，返回所有指标（内置 + 扩展）。

        流程:
        1. 构建带参数的 FDI，执行因子
        2. 3 折交叉验证计算内置指标 (rankic, icir, win_rate, max_drawdown, turnover)
        3. 调用所有 custom_metric_calculators 计算扩展指标
        4. 合并为统一字典返回

        Returns:
            {"rankic": float, "icir": float, ..., "sector_neutral_ic": float, ...}
        """
        # 构建带参数的 FDI
        fdi = self._build_fdi_with_params(params)

        # 执行因子
        factors = factor_obj.replay(fdi)
        factor = factors[0]
        price_data = self._get_price_data(fdi)

        # 3 折滚动窗口交叉验证 — 内置指标
        all_metrics = []
        for fold_start, fold_end in self._get_cv_folds():
            fold_fdi = self._subset_fdi(fdi, fold_start, fold_end)
            data = factor.readData(...)
            fold_price = self._get_price_data(fold_fdi)
            fold_metrics = self._calc_ic_metrics(data, fold_price)
            all_metrics.append(fold_metrics)

        # 各折内置指标取均值
        keys = all_metrics[0].keys()
        result = {k: np.mean([m[k] for m in all_metrics]) for k in keys}

        # 扩展指标 — 调用用户注册的 MetricCalculator
        calculators = self.config.custom_metric_calculators or []
        for calc in calculators:
            try:
                extra = calc.calculator(factor, price_data, fdi, params)
                if extra:
                    result.update(extra)
            except Exception as e:
                # 计算器异常不影响整体搜索，记录警告并跳过
                logging.warning(f"MetricCalculator {type(calc).__name__} 异常: {e}")

        return result

    def _calc_sensitivity(self, study, search_space) -> dict:
        """计算参数敏感性分析。"""
        sensitivity = {}
        for name in search_space:
            trials = study.trials
            values = [t.params.get(name) for t in trials if t.value is not None]
            rankic_values = [t.value for t in trials if t.value is not None]
            sensitivity[name] = {
                "values": values,
                "rankic_values": rankic_values,
            }
        return sensitivity
```

```
│ log_node     │  ← 写入 MiningLogDB
└──────┬──────┘
       │
       ▼
    [END]
```

### 9.2 状态定义

```python
from typing import TypedDict, Optional

class DevelopmentState(TypedDict):
    hypothesis: dict                    # 假设生成阶段 输入
    config: DevelopmentConfig
    workspace_dir: str                  # 工作区路径
    generated_code: Optional[GeneratedCode]
    validation_report: Optional[ValidationReport]
    search_result: Optional[SearchResult]
    factor_object: Optional[FactorObject]
    error: Optional[str]
    attempt: int                        # 当前修复尝试次数
```

### 9.3 节点实现

```python
async def generate_node(state: DevelopmentState) -> dict:
    """代码生成节点。"""
    generator = CodeGenerator(state["config"])
    generated = generator.generate(state["hypothesis"])
    
    # 保存到工作区
    ws = WorkspaceManager()
    ws_dir = Path(state["workspace_dir"])
    ws.save_factor_code(ws_dir, generated.factor_code, generated.factor_module_name)
    ws.save_metadata(ws_dir, generated.metadata)
    ws.save_search_space(ws_dir, generated.search_space)
    
    return {"generated_code": generated}


async def verify_node(state: DevelopmentState) -> dict:
    """验证节点。"""
    verifier = VerificationPipeline(state["config"])
    report = verifier.run_all(state["workspace_dir"], state["hypothesis"])
    return {"validation_report": report, "attempt": state["attempt"] + 1}


async def fix_node(state: DevelopmentState) -> dict:
    """自动修复节点。"""
    generator = CodeGenerator(state["config"])
    ws_dir = Path(state["workspace_dir"])
    code = (ws_dir / f"{state['generated_code'].factor_module_name}.py").read_text()
    
    failed = [v for v, r in zip(...) if not r.passed]
    fixed_code = generator.fix(code, state["hypothesis"], failed)
    
    ws = WorkspaceManager()
    ws.save_factor_code(ws_dir, fixed_code, state["generated_code"].factor_module_name)
    
    return {}


async def search_node(state: DevelopmentState) -> dict:
    """参数搜索节点。"""
    searcher = ParamSearcher(state["config"])
    search_space = state["generated_code"].search_space
    
    if not search_space:
        return {"search_result": SearchResult(best_params={}, ...)}
    
    result = searcher.search(state["workspace_dir"], search_space)
    
    ws = WorkspaceManager()
    ws.save_search_result(Path(state["workspace_dir"]), result)
    
    return {"search_result": result}


async def log_node(state: DevelopmentState) -> dict:
    """写入 MiningLogDB。"""
    writer = MiningLogWriter()
    hypothesis = state["hypothesis"]
    
    writer.start_run(
        run_id=f"FM_{hypothesis['hypothesis_id']}",
        hypothesis_id=hypothesis["hypothesis_id"],
        factor_name=hypothesis["factor_name"],
        category=hypothesis["category"],
    )
    
    writer.record_development(
        code_path=state["factor_object"].dir_path / "factor_def.py",
        best_params=state["search_result"].best_params,
        auto_fix_count=state["validation_report"].auto_fix_count,
    )
    
    return {}
```

### 9.4 条件边

```python
def after_verify(state: DevelopmentState) -> str:
    """验证后路由。"""
    report = state["validation_report"]
    if report.all_passed:
        return "search"
    elif state["attempt"] < state["config"].max_auto_fixes:
        return "fix"
    else:
        return "end_needs_manual"

def after_fix(state: DevelopmentState) -> str:
    """修复后路由。"""
    return "verify"  # 回到验证节点
```

### 9.5 图编译

```python
from langgraph.graph import StateGraph, END

def build_development_graph() -> StateGraph:
    graph = StateGraph(DevelopmentState)
    
    # 添加节点
    graph.add_node("generate", generate_node)
    graph.add_node("verify", verify_node)
    graph.add_node("fix", fix_node)
    graph.add_node("search", search_node)
    graph.add_node("log", log_node)
    
    # 添加边
    graph.set_entry_point("generate")
    graph.add_edge("generate", "verify")
    graph.add_conditional_edges("verify", after_verify, {
        "search": "search",
        "fix": "fix",
        "end_needs_manual": END,
    })
    graph.add_edge("fix", "verify")
    graph.add_edge("search", "log")
    graph.add_edge("log", END)
    
    return graph.compile()
```

## 10. Skill 模式

### 10.1 两个 Skill 的分工

Skill 模式由两个独立 skill 组成，`ensure_skills()` 自动将两者链接到 `.claude/skills/` 下：

| Skill 名 | 目录 | 职责 |
|----------|------|------|
| `generate-factor-def-code` | `QSExt/FactorDef/skill/generate-factor-def-code/` | 生成因子定义代码，包含完整 API 参考（`factor_def_api.md`） |
| `develop-factor` | `QSExt/LLMFactor/development/skill/develop-factor/` | 完整开发流水线（代码生成 → 验证 → 参数搜索 → 汇总），Step 1 引用 `generate-factor-def-code` |

### 10.2 主 Skill: `/develop-factor`

```markdown
# /develop-factor

从假设文档开发因子。

## 用法
/develop-factor <hypothesis_yaml_path>

## 流程
1. 加载假设文档
2. 代码生成（Step 1）—— 查阅 `/generate-factor-def-code` 获取 FactorDef API 参考
3. 验证（Step 2）
4. 修复循环（最多 3 次）
5. 参数搜索（Step 3）
6. 保存工作区（Step 4）
7. 写入 MiningLogDB

## 输出
DevelopmentResult 对象，包含因子目录路径和评测结果
```

### 10.3 单步骤独立调用

通过 `--step` 参数可独立调用某个步骤：

- `/develop-factor --step generate`: 仅代码生成
- `/develop-factor --step verify`: 仅验证（接受因子目录路径）
- `/develop-factor --step search`: 仅参数搜索（接受因子目录 + 搜索空间）

各步骤的详细规范见 `skill/develop-factor/references/` 目录下的参考文档。

## 14. 端到端测试发现的问题与修复

### 14.1 代码生成器问题

| 问题 | 修复 |
|------|------|

| 代码保存为 `{module_name}.py` 但验证器找 `factor_def.py` | `generate_node` 同时保存两份文件 |

### 14.2 LangGraph 图问题

| 问题 | 修复 |
|------|------|
| 验证失败时 `arun_development` 返回 None | 构造 `validation_failed` 结果返回 |
| `generate_node` 缺少 README.md 生成 | 添加 `_build_readme()` 辅助函数 |
| `log_node` 缺少 `validation_summary.json` | 添加汇总 JSON 写入逻辑 |

### 14.3 LLM 代码质量问题

| 问题 | 原因 | 缓解 |
|------|------|------|
| LLM 使用错误的 import 路径 | `QuantStudio.Factor.FactorDef` 不存在 | API 参考中明确列出正确路径 |
| LLM 访问 `fdi.Args` 属性 | `FactorDefInput` 无此属性 | 在 prompt 中说明参数传递方式 |
| Skill 模式代码质量明显更高 | Claude 可自主查询数据库表结构 | 优先使用 Skill 模式 |

## 15. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| **LLM 生成的代码质量不稳定** | 验证通过率低，修复循环次数多 | 经验引用 + 详细的 prompt + 多轮修复；Skill 模式质量更高 |
| **未来信息泄漏检测的时序截断测试耗时长** | 验证阶段耗时增加 | 对仅使用财务数据的因子跳过测试 |
| **Optuna 搜索在大空间下收敛慢** | 参数搜索耗时增加 | 合理设置搜索空间范围 + 早停 |
| **LLM 幻觉（编造表名/字段名）** | 代码不可执行 | Agent A 表名验证 + Agent B 执行验证 |
