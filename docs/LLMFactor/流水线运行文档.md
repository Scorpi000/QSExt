# 流水线运行文档

> 因子挖掘系统的端到端流水线和持续挖掘循环的使用指南。
>
> 最后更新：2026-08-04

---

## 一、概述

因子挖掘系统提供两种运行模式（Skill / Graph）和两种运行方式（单次 / 持续循环）。

### 1.1 脚本结构

```
scripts/
├── _utils.py                    # 共享工具（日志、skill 链接、消息格式化等）
├── run_hypothesis.py            # 假设生成（独立运行）
├── run_development.py           # 因子开发（独立运行）
├── run_evaluation.py            # 因子评测（独立运行）
└── run_pipeline.py              # 编排入口（串联三个阶段 + 持续循环）
```

| 脚本 | 用法 |
|------|------|
| `run_hypothesis.py` | 独立运行假设生成，输出 `hypothesis.yaml` |
| `run_development.py` | 独立运行因子开发，需要假设 YAML，输出 `factor_def.py` |
| `run_evaluation.py` | 独立运行因子评测，需要因子目录，输出评测报告 |
| `run_pipeline.py` | 编排以上三个阶段的完整流水线，支持持续循环 |

### 1.2 Skill 环境

Skill 模式需要三个 skill 链接到 `.claude/skills/`：

| Skill 名 | 源目录 |
|----------|--------|
| `hypothesis` | `QSExt/LLMFactor/hypothesis/skill/hypothesis` |
| `develop-factor` | `QSExt/LLMFactor/development/skill/develop-factor` |
| `generate-factor-def-code` | `QSExt/FactorDef/skill/generate-factor-def-code` |

`ensure_skills()` 函数自动创建链接，`develop-factor` 的 Step 1 代码生成会查阅 `generate-factor-def-code` 获取 FactorDef API 参考。

## 二、配置体系

### 2.1 配置文件结构

```
LLMFactor/config/
├── pipeline.yaml           # 流水线全局配置
├── hypothesis_research.yaml   # 假设生成配置
├── development.yaml           # 因子开发配置
└── evaluation.yaml            # 因子评测配置
```

### 2.2 pipeline.yaml — 全局配置

```yaml
# 项目根目录
# "auto": 自动查找（QSExt/ 的父目录，要求含 .mcp.json）
# 绝对路径: 如 "D:/HST/QSExt"
project_root: auto

# Claude CLI 配置
# "auto": 从 PATH 或已知路径自动查找
# 绝对路径: 如 "C:/Users/xxx/.local/bin/claude.exe"
claude_cli: auto

# 产出物输出基础目录
# 支持绝对路径或相对于项目根目录的路径
# 实际输出目录会自动追加 FM_<时间戳> 子目录
# 例: "workspace" → <项目根>/workspace/FM_20260710_143000/
workspace_dir: "workspace"

# Agent 最大轮次（命令行参数 --max-turns-hypothesis/development 可覆盖）
max_turns_hypothesis: 50
max_turns_development: 80

# 数据上下文（构建因子对象和评测参数时使用）
data:
  trade_day_start: "2000-01-01"   # DTRuler 起始日
  trade_day_end: "2025-12-31"     # DTRuler 截止日
  stock_date: "2025-06-30"        # 股票截面选取日期
  max_stocks: 1000                # 最大股票数量
```

### 2.3 各阶段配置

| 文件 | Config 类 | 说明 |
|------|-----------|------|
| `hypothesis_research.yaml` | `ResearchConfig` | 市场、频率、搜索预算、方向冻结策略 |
| `development.yaml` | `DevelopmentConfig` | LLM 模型、验证开关、参数搜索配置 |
| `evaluation.yaml` | `EvalConfig` | 样本内/外区间、分组数、入库阈值、评分权重、缓存配置 |

### 2.4 统一加载方式

所有脚本通过 `--config` 参数指定全局配置文件路径（默认 `LLMFactor/config/pipeline.yaml`），由 `PipelineConfig` 统一加载并分发给各阶段：

```python
from QSExt.LLMFactor.pipeline_config import PipelineConfig

pipeline_config = PipelineConfig.from_yaml("LLMFactor/config/pipeline.yaml")
project_root = pipeline_config.resolve_project_root()
cli_path = pipeline_config.resolve_claude_cli()
hypothesis_config = pipeline_config.load_hypothesis_config()
development_config = pipeline_config.load_development_config()
evaluation_config = pipeline_config.load_evaluation_config()
```

### 2.5 命令行参数优先级

命令行参数优先于配置文件值：

```bash
# 配置文件中 max_turns_hypothesis=50，命令行覆盖为 30
python -m QSExt.LLMFactor.scripts.run_pipeline_skill \
  --max-turns-hypothesis 30 --target "动量因子"
```

## 三、单次流水线

统一的编排入口是 `run_pipeline.py`，通过 `--mode` 选择 Skill 或 Graph 模式，通过 `--stages` 选择运行阶段。

### 3.1 完整流水线

```bash
cd d:/HST/QSExt

# Skill 模式（默认）
python -m QSExt.LLMFactor.scripts.run_pipeline --target "动量因子"

# Graph 模式
python -m QSExt.LLMFactor.scripts.run_pipeline --mode graph --target "动量因子"

# 指定方向
python -m QSExt.LLMFactor.scripts.run_pipeline --target "动量因子" --direction "动量/短期反转"

# 指定配置文件
python -m QSExt.LLMFactor.scripts.run_pipeline --config my_pipeline.yaml --target "估值因子"
```

### 3.2 分段运行

通过 `--stages` 参数选择性运行某个阶段，便于分段调试：

```bash
# 仅运行假设生成
python -m QSExt.LLMFactor.scripts.run_pipeline --target "动量因子" --stages hypothesis

# 假设生成 + 因子开发（跳过评测）
python -m QSExt.LLMFactor.scripts.run_pipeline --target "动量因子" --stages hypothesis,development

# 从已有假设开始（跳过假设生成）
python -m QSExt.LLMFactor.scripts.run_pipeline \
  --stages development --hypothesis-yaml workspace/hypothesis/hypothesis.yaml

# 已有因子目录，直接评测
python -m QSExt.LLMFactor.scripts.run_pipeline \
  --factor-dir local/workspace/FM_xxx/development
```

### 3.3 独立脚本调用

也可以直接调用各阶段脚本，每个脚本支持独立的参数：

```bash
# 假设生成
python -m QSExt.LLMFactor.scripts.run_hypothesis --target "动量因子"
python -m QSExt.LLMFactor.scripts.run_hypothesis --mode graph --target "动量因子"

# 因子开发（需要假设 YAML）
python -m QSExt.LLMFactor.scripts.run_development --hypothesis workspace/hypothesis/hypothesis.yaml

# 因子评测（需要因子目录）
python -m QSExt.LLMFactor.scripts.run_evaluation --factor-dir workspace/FM_xxx/development
```

## 四、持续挖掘循环

### 4.1 基本用法

通过 `--max-rounds` 参数启用持续循环模式：

```bash
# 运行 10 轮持续挖掘
python -m QSExt.LLMFactor.scripts.run_pipeline --max-rounds 10

# 指定研究目标
python -m QSExt.LLMFactor.scripts.run_pipeline \
  --target "动量因子" --max-rounds 5

# 设置时间上限（小时）
python -m QSExt.LLMFactor.scripts.run_pipeline \
  --max-rounds 10 --max-hours 4

# 指定配置文件
python -m QSExt.LLMFactor.scripts.run_pipeline \
  --config my_pipeline.yaml --max-rounds 5
```

**参数说明：**

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--config` | `LLMFactor/config/pipeline.yaml` | 流水线配置文件路径 |
| `--target` | 全部 | 研究目标（动量因子、估值因子、全部） |
| `--max-rounds` | 10 | 最大轮次 |
| `--max-hours` | 8.0 | 最大运行时间（小时） |
| `--mode` | skill | 运行模式（skill / graph） |
| `--max-turns-hypothesis` | 从配置文件读取 | 假设生成阶段最大轮次 |
| `--max-turns-development` | 从配置文件读取 | 因子开发阶段最大轮次 |

### 4.2 方向调度策略

系统使用 `BudgetAllocator` 的评分公式自动选择下一个研究方向：

```
score = wiki_potential × (0.3 + 0.7 × success_rate) × (0.2 + 0.8 × unexplored_ratio)
```

- **success_rate**: 该方向历史成功率（已入库 / 总尝试）
- **unexplored_ratio**: `1/(1+attempts)`，鼓励探索新方向
- **wiki_potential**: 知识库中该方向的内容丰富度

每轮结束后，结果写入 MiningLogDB，下一轮重新查询覆盖率，实现闭环反馈。

### 4.3 预定义方向目录

系统内置以下研究方向：

| 类别 | 方向 |
|------|------|
| 动量 | 短期反转、中期动量、动量因子 |
| 估值 | EP_TTM、BP_MRQ、SP_TTM |
| 波动率 | 低波动率、特质波动率 |
| 流动性 | 换手率、非流动性 |
| 质量 | ROE、毛利率 |
| 技术 | 量价背离、成交额分布 |

可通过修改 `run_mining_loop.py` 中的 `DIRECTION_CATALOG` 扩展。

### 4.4 产出物结构

```
workspace/
├── mining_loop.log               # 循环日志
└── loop_{timestamp}/
    ├── loop_summary.json         # 循环总汇总
    ├── round_001/
    │   ├── pipeline.log
    │   ├── pipeline_summary.json
    │   ├── hypothesis/
    │   ├── development/
    │   └── evaluation/

    └── ...
```

## 六、Graph 模式 vs Skill 模式对比

| 维度 | Graph 模式 | Skill 模式 |
|------|-----------|-----------|
| 假设生成阶段耗时 | ~9 分钟 | ~5 分钟 |
| 因子开发阶段耗时 | ~6 分钟 | ~51 分钟 |
| 代码质量 | LLM 可能生成语法错误 | Claude 自主查询数据库，质量更高 |
| 可复现性 | 高（确定性流程） | 低（Claude 自主决策） |
| 适用场景 | 批量生产、自动化 | 探索性研究、首次运行 |
| MCP 工具使用 | 通过 LangChain 适配器 | Claude 直接调用 |
| 自动修复 | LangGraph 节点循环 | Claude 自主判断修复策略 |

**建议：**
- 首次运行或探索新方向时使用 **Skill 模式**（代码质量更高）
- 批量生产或持续循环时使用 **Graph 模式**（速度更快、成本更低）

## 八、常见问题

### Q: 因子开发阶段代码生成反复失败怎么办？

A: Skill 模式下 Claude 会自动查询数据库表结构，代码质量更高。如果 Graph 模式反复失败，尝试切换到 Skill 模式。

### Q: 因子评测阶段报错"时点标尺长度不足"怎么办？

A: 因子使用了较大的回溯窗口（如 `Lag(lookback=1)` + `RollingApply(window=20)`）。修改 `pipeline.yaml` 中的 `data.trade_day_start`，将其提前以提供更多缓冲：

```yaml
data:
  trade_day_start: "2000-01-01"  # 提前到足够早的日期
```

### Q: 如何查看 Claude Agent 的完整推理过程？

A: 查看 `hypothesis/claude_output.txt` 和 `development/claude_output.txt`，其中包含：
- `[thinking]` — Agent 内部推理
- `[tool_use] 工具名` — MCP 工具调用及输入参数
- `[tool_result] id=...` — 工具返回结果
- 普通文本 — 最终输出

也可查看 Claude CLI 会话日志：`~/.claude/projects/D--HST-QSExt/*.jsonl`

### Q: 持续循环中途停止了怎么办？

A: 每轮结果都已保存到 `round_NNN/` 目录和 `loop_summary.json`。可以查看已完成的轮次，调整参数后重新启动。

### Q: 如何加速多轮评测？

A: 评测阶段支持 `FeatherFactorCache` 缓存，可在 `evaluation.yaml` 中配置：

```yaml
# 缓存配置
cache_enabled: true               # 启用缓存
cache_dir: null                   # null = 使用系统临时目录，指定固定路径可跨次复用
cache_start_mode: "continue"     # "continue" 复用已有缓存，"new" 每次清空
```

**缓存行为：**
- `cache_enabled: true` — 评测时自动缓存因子计算结果到 `FeatherFactorCache`
- `cache_enabled: false` — 不使用缓存，每次重新计算
- `cache_dir: null` — 使用系统临时目录（重启后失效）
- `cache_dir: "/固定路径"` — 持久化缓存，跨次运行也能复用
- `cache_start_mode: "continue"` — 复用已有缓存；若 `state.pkl` 不存在则自动降级为 `new` 模式并给出警告
- `cache_start_mode: "new"` — 每次清空缓存重新计算

**多轮挖掘循环中的缓存共享：**
- `RoundRunner` 持有 `EvalCacheManager`，跨轮次共享同一 Cache 实例
- 样本内（IS）和样本外（OOS）评测共享同一 Cache
- 实测加速比约 1.6x（正式计算阶段可达 5.5x），具体取决于因子复杂度和数据量
